## 3. ReplayMod

- mc_version: Java 1.8〜26.3（Fabricは1.14以上、Forgeは1.12.2以下）
- 確度: 【一次】（`replaymod_docs`）

| 項目 | 内容 |
|---|---|
| 記録 | 設定で有効にすると、すべてのプレイを自動で記録する。**ワールドに入った時点から**でないと記録できない |
| 記録の範囲 | 読み込まれたチャンク全部。サーバでは `view-distance` まで |
| 記録中の目印 | Mキーで Event Marker。後から名前を付けられる |
| リプレイ内の移動 | スペクテイターと同じ。マウスホイールで飛ぶ速さ。J／L／Kでロール |
| 再生速度 | 0.1倍〜8倍。Pで一時停止（止めたまま飛べる） |
| カメラパス | Position Keyframe（位置・向き・ロール）、Time Keyframe（世界の時刻）、Spectator Keyframe（乗り移り）。タイムラインは最長10分 |
| 補間 | 既定は3次スプライン。Oキーで直線と切り替え |
| 経路の確認 | Hキーで赤い線を表示 |
| キーフレームの保存 | Xキーの Keyframe Repository。リプレイごとに複数のプリセット |
| 書き出しの方式 | 通常、ステレオ（3D）、Cubic、Equirectangular（360°） |
| 書き出しの設定 | 解像度は自由（例: 1920×1080、3840×2160）。エンコードのプリセットは7種類で、既定はMP4（x264） |
| 合成向け | 空を単色にするChroma Keying、Depth Map（OpenEXRのみ。アンチエイリアスは使えない） |
| 表示 | 名札の描画を切れる。Player Overview（Bキー）でプレイヤーごとに非表示 |
| 暗い場面 | Ambient Lighting（Zキー）。暗視のように空の色が変わらない |
| Quick Mode | Qキー。時間の移動が速くなる代わりに、プレビューでパーティクルなどが出ない |
| 互換性 | 1.16.5以上はIrisに対応。Sodiumは、書き出しに専用ビルドが必要とある |

- 非公式のアドオン **ReplayModCinematics** がある【二次】（`yt_30_o6SfiEhk` の概要欄）。ショットのプリセット、点を1つずつ置く経路、点の間の停止・速さ・イージング、注視する相手と追跡、プレイヤー・モブ・矢への追従ショット、Time Keyframe と連結、を扱うとある。Forge 1.20.1 か NeoForge 1.21.1 と、ReForgedPlay が必要。Fabricでは使えない。
- 上級者向けの解説として、slicedlime の6回シリーズがある（`yt_P1bGz5ykIFE`、2016年）。第1回のチャプターは「カメラパスの計画」「再生の遅れへの対処」「補間の理解」「書き出しの進め方」【二次】。古い版の話なので、今の版に当てはまるかは未確認。

## 4. コマンドで経路を与えられる道具（全自動の候補）

`docs/MC実行基盤.md` §4 の「全自動」は自作のクライアントmodを想定している。その前に試せる既製の道具が2つある。どちらも**録画の機能は持たない**ので、画面録画ソフトと組み合わせることになる。

### CMDCam

- mc_version: Java 1.18.2〜26.3（Forge、NeoForge）
- 確度: 【一次】（`cmdcam_modrinth`。作者の説明文）
- 主なコマンド:

| コマンド | 働き |
|---|---|
| `/cam add [location:x,y,z] [rotation] [roll] [fov]` | 点を追加する |
| `/cam insert <index> …`・`/cam set <index>`・`/cam remove <index>`・`/cam clear` | 点の挿入・更新・削除・全消去 |
| `/cam start <time:ms\|s\|m\|h\|d> [loops]` | 指定した長さで再生する（キー操作での既定は10秒。loops は -1 で無限） |
| `/cam interpolation <linear,cosine,cubic,hermite,circular>` | 補間。既定は hermite |
| `/cam distance_timing <false\|true>` | 距離に応じた時間配分。等速にできる |
| `/cam smooth_start <false\|true>` | 始まりをなめらかにつなぐ |
| `/cam spinning_fix <fix\|fix_keep_direction\|no_fix>` | 360°をまたぐ回転の解釈。既定は fix_keep_direction |
| `/cam target <none\|self\|entity\|pos\|select\|player>` | 注視する相手 |
| `/cam follow <none\|self\|entity\|pos\|select\|player>` | 位置を追う相手 |
| `/cam pitch step <number>`・`yaw step`・`pos step` | 追う速さ。1が即時、既定は20 |
| `/cam mode <default\|outside>` | outside は、プレイヤーを操作しながらカメラにもなれるモード |
| `/cam show <種類>`・`/cam hide <種類>` | 経路の表示・非表示 |
| `/cam save <name>`・`/cam load <name>` | 経路と設定の保存・読み込み（ワールドごと） |
| `/cam-server start <path> <players> [time] [loops]` | サーバ側から、指定したプレイヤーに経路を再生させる |
| `/cam-server create <name>`・`/cam-server get <name> <camのコマンド>` | サーバ側で経路を作り、`/cam` と同じ設定をその経路に対して行う |

- 注意: 配布ページに「you need an external tool to record it」とある。「クライアント側では @a、@p、@e が使えない」ともある。
- 検討点【未確認】:
  - FlashbackはFabric、CMDCamはForge／NeoForgeなので、同じクライアントに入れるのは難しい。非公式のFabric移植があるという情報がある（`web_cmdcam_search`）。
  - 実時間の画面録画になるので、コマ落ちすれば画に出る。リプレイ方式（`カメラワーク.md` [CW-03]）の利点がない。

### Cinemalya（バニラのデータパック）

- mc_version: Java 26.2〜26.3
- 確度: 【一次】（`cinemalya_modrinth`。作者の説明文）
- 仕組み: 見えない `item_display` を経路に沿って動かし、プレイヤーにそれを観戦させる。経路は開始時に1回だけ計算する（スプラインの計算は Bookshelf Spline を使う）。
- 呼び出しの例（説明文から）:

```mcfunction
execute as <player> run function #cinemalya:v1/launch_path {with:{duration:90,ease:"ease_in_out",waypoints:[{args:[-112,75,-21,-30,4]},{args:[-116,77,28,-121,16]},{args:[-72,68,20,92,-11.7]}]}}
```

| 項目 | 内容 |
|---|---|
| ウェイポイント | `args:[x,y,z,yaw,pitch,duration]`。相対座標の書き方もある。最大128個 |
| 時間 | tick単位。`duration` の上限は36000（30分）。フレーム数の上限は600で、超えると刻みが粗くなる |
| イージング | linear、ease_in、ease_out、ease_in_out。経路全体にも、区間ごとにも付けられる |
| スプライン | 2点はベジェ、3点以上はCatmull-Rom |
| 等速 | 時間を指定しない区間は、長さに比例して時間を割り振る |
| 回転の精度 | `カメラワーク.md` [CW-32] の回避策を既定で使う |
| ゲーム内の編集 | 専用のアイテムでキーフレームを置き、コマンドとして書き出せる |
| 必要なもの | LanternLoad、Bookshelf Spline |

- 検討点【未確認】:
  - 関数の呼び出し1つなので、`lab/runner.py` と同じRCON経由で実行できる見込みがある。`experiment.yaml` の `shots` から自動で作りやすい。
  - カメラ役はゲームのtickで動くので、`/tick rate` で世界を遅くするとカメラも遅くなるはず。
  - 対応が26.2以降だけ。同じ仕組み（displayエンティティ＋観戦）を自前のデータパックで作る選択肢もある。

### Cutscene Maker Pro（Cinemalyaと同じ方式の別のデータパック）

- mc_version: Java 26.3
- 確度: 【一次】（`cutscene_maker_pro_modrinth`。作者の説明文）
- カメラは `item_display` で、プレイヤーがそれを観戦する。Cinemalyaと同じ仕組みを使っている。
- 作者が挙げている制約: 1区間の移動は59tickまで。サーバでは `allow-flight=true` が必要（カメラを高速で追う観戦が、不正対策で切断されることがある）。
- 2つの独立したデータパックが同じ方式を取っているので、「displayエンティティ＋観戦」はバニラでカメラを動かす定番の方法と見てよさそう【未確認】。

### CineCam

- mc_version: Java 26.1.2（Fabric、Forge）
- 確度: 【一次】（`cinecam_modrinth`）
- ポイントごとに、位置、向き、FOV（1〜179°）、Hold（留まる時間）、Travel（次の点までの時間）、追尾する相手、追尾のなめらかさを持つ。移動の種類は MOVE／CUT／SMOOTH／LINEAR／SPLINE。
- シーンは `cinecam/scenes/default.json` に保存される。JSONの書式がわかれば外から作れる【未確認】。
- 公開から日が浅く、ダウンロード数も少ない（調査時点で351）。

## 6. 統合版の `/camera`（参考。Java版にはない）

- mc_version: 統合版 1.20.30〜（実験的機能としては1.20.0〜）
- 確度: 【二次】（`wiki_camera_cmd`）
- プリセット（free、first_person、third_person、third_person_front、follow_orbit、fixed_boom）を選び、freeでは `pos`（位置）、`rot`（向き）、`facing`（注視）、`ease <時間> <種類>`（イージング）を指定する。イージングは32種類。ほかに `fov_set`、`fade`、`target_entity`、`play_spline`。
- Java版では使えないが、「1つのカメラ移動 = 位置・向き（または注視）・時間・イージング」という書き方は、`experiment.yaml` の `shots` を拡張するときの参考になる。
- YouTubeには統合版のこのコマンドの解説が多い（`sources.yaml`）。検索するときに、Java版の情報と混ざらないよう注意する。
