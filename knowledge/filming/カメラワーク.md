# カメラワーク（仕組みと、うまく撮るための決まり）

状態: **文献調査のみ（2026-11-19）。MC内での実測は1件もない。** P2（撮影の試作）で【実測】に上げる。
対象: Java版。このリポジトリのMCバージョンは未決定（P0）なので、各項目の `mc_version` には根拠にした資料の対応バージョンを書いた。

- カメラワークの**種類**ごとの定義・使いどころ・作り方は [`camera_moves.yaml`](camera_moves.yaml)。
- この文書は、それらに共通する**仕組み**と**決まり**をまとめる。
- 道具（mod・コマンド）ごとの機能は [`撮影ツール.md`](撮影ツール.md)、出典の一覧は [`sources.yaml`](sources.yaml)。
- 見出しが事実の一文。`[CW-nn]` は他のファイルから参照するための番号（欠番・追加可、振り直さない）。
- 「根拠」の `replaymod_docs` などは `sources.yaml` の `id`。

## 0. 先に結論

1. **記録してから撮る。** 画面を録画しながらカメラを操作するのではなく、世界の出来事をリプレイとして記録し、後からカメラを付けて、mod内蔵のレンダラで書き出す（[CW-01]〜[CW-03]）。
2. **カメラの動きはキーフレームと補間で作る。** 決めるのは「位置・向き・ロール・FOV」と「いつ」。間はソフトが埋める（[CW-05]〜[CW-12]）。
3. **カメラの時間と世界の時間は別物。** スロー・時間停止・タイムラプスは、世界の時間だけを伸び縮みさせて作る（[CW-15]〜[CW-21]）。
4. **なめらかに見えない原因は、主に4つに分けられる。** 補間の種類が合っていない、速さがむら、回転が遠回り、20tickの刻みがそのまま出ている（§11。対策の一部はまだ試していない）。
5. **物理の動画では「計測ショット」と「演出ショット」を分ける。** 計測ショットは固定・真横・被写体を1つの面に並べる。数字の根拠にする画でカメラを動かさない（§12、提案）。

## 1. 調査の方法と限界

- 調べたもの: YouTubeの解説動画（マイクラのシネマティック撮影、Flashback、Replay Mod、コマンドによるカメラ）、modの公式ドキュメント・配布ページ・変更履歴、Minecraft Wiki。
- **YouTubeは動画ページの題名・概要欄・チャプターまでしか読めていない。** 字幕（発話内容）の取得はYouTube側のbot判定で止められ、映像も見ていない。したがって「どの動画が何を扱っているか」はわかるが、「動画の中で具体的にどう説明しているか」は未確認。動画の中身に依存する項目は【二次】か【未確認】にした。
- この調査で【一次】としたのは、modの作者自身が書いた公式ドキュメント・配布ページ・変更履歴を読んで確認したもの。ソースコードは読んでいない。
- Minecraft Wikiと、Web検索の要約から得たものは【二次】。記憶や幾何学からの推論は【未確認】。

## 2. 記録してから撮る（リプレイ方式）

### [CW-01] シネマティックな映像は「記録 → 後からカメラを付ける → 書き出す」の順で作る
- mc_version: Java 1.21〜26.3（Flashback）、Java 1.8〜26.3（ReplayMod）
- 確度: 【一次】（手順そのもの）／「主流である」は【二次】
- 根拠: `replaymod_docs` の 2. Recording → 3. Replaying → 3.3 Camera Paths → 3.4 Rendering。`flashback_modrinth` の説明「Record your Minecraft gameplay, play it back and create stunning cinematic shots」。題名を確認した解説動画67本のうち34本がこの2つのmodを題材にしている（Flashback 15本、ReplayMod 19本。残りは統合版、コマンドやデータパック、ほかのmodなど。`sources.yaml` の `meta`）。

### [CW-02] リプレイには画面ではなく世界の状態が記録されるので、1回の記録から何通りでもカメラを付け直せる
- mc_version: ReplayMod（Java 1.8〜26.3）
- 確度: 【一次】
- 根拠: `replaymod_docs` FAQ。読み込まれたチャンクは背後のものも含めて記録される。10分のリプレイで2〜10MB程度。サーバでは `view-distance` の範囲まで。
- 注意: ReplayModは**ワールドに入った時点から**記録を始める必要があり、途中からは始められない（同FAQ）。

### [CW-03] 書き出しはmod内蔵のレンダラが行い、解像度とフレームレートを指定できる。画面録画ソフトは要らない
- mc_version: ReplayMod、Flashback（上と同じ）
- 確度: 【一次】
- 根拠: `replaymod_docs` 3.4「render Camera Paths to videos without using a screen recording tool」。`flashback_modrinth` のギャラリー「Export Options … Change the resolution, framerate, video settings, and even capture audio」。
- 補足【二次】: 実時間ではなく1コマずつ描いて書き出すので、PCが遅くても滑らかな動画になる、という説明が複数ある（`web_pmc_cinematic_blog`、`yt_NaCNpdQGIWw` の題名）。仕組みとして確認したわけではない。

### [CW-04] リプレイ方式なら、乱数を含む現象でも全アングルが「同じ1回」になる
- mc_version: 同上
- 確度: 【未確認】（[CW-02] からの推論）
- 根拠: 記録は1回で、カメラだけを変えて何度も書き出せるため。
- このリポジトリとの関係: `docs/MC実行基盤.md` §5 は「乱数を使う現象は再実行しても完全には一致しない」としている。リプレイで撮れば、TNTのような現象でも多視点の画が食い違わない。P2で確かめる。

## 3. カメラを決める量

### [CW-05] カメラの状態は「位置 x,y,z・向き yaw,pitch・ロール」の6つとFOVで表される
- mc_version: ReplayMod、CMDCam（1.18.2〜26.3）、CineCam（26.1.2）
- 確度: 【一次】
- 根拠: `replaymod_docs` 3.3.3「A Position Keyframe stores a Camera Position (x, y, z, yaw, pitch, roll)」。`cmdcam_modrinth` の `/cam add [location] [rotation] [roll] [fov]`。`cinecam_modrinth` の Point Settings（X/Y/Z、Yaw/Pitch、FOV、Hold、Travel）。
- 使い方: ショットを機械可読に書くなら、この7つの数と時刻の組（＝キーフレーム）の列にすれば、どの道具にも移せる。

### [CW-06] MCのFOV設定値は「縦方向の視野角」で、標準は70、設定できる範囲は30〜110
- mc_version: Java版（Wikiの現行記事）
- 確度: 【二次】
- 根拠: `wiki_options`。横の視野角はアスペクト比で決まる。16:9での対応は 30→50.9°、50→79.3°、70→102.4°、90→121.3°。
- 補足: modはこの範囲を超えられる。CineCamは1〜179°（`cinecam_modrinth`）。

### [CW-07] 投影は透視（通常）のほかに正投影も選べる（Flashback 0.40.0 以降）
- mc_version: Java 26.1〜（Flashback 0.40.0 の対応バージョン）。1.21.x 向けの 0.39.x 系にあるかは【未確認】
- 確度: 【一次】
- 根拠: `flashback_changelog` 0.40.0「Added "Orthographic" projection」。同じ版でCube MapとEquirectangularも追加。
- 意味: 正投影は遠近感がなく、奥行きによって大きさが変わらない。真横から撮ると図面のような画になる（[CW-27]）。

## 4. キーフレームと補間

### [CW-08] カメラの動きは、キーフレーム（ある時刻のカメラの状態）を置き、その間をソフトが補間して作る
- mc_version: ReplayMod、Flashback、CMDCam、CineCam
- 確度: 【一次】
- 根拠: `replaymod_docs` 3.3。`flashback_modrinth`「Keyframe a variety of elements and interact with them directly on the timeline」。
- 補足: ReplayModのキーフレームのタイムラインは最長10分（同 3.3.2）。

### [CW-09] 補間には「直線」と「曲線（スプライン）」があり、既定は曲線
- mc_version: 同上
- 確度: 【一次】
- 根拠: ReplayModの既定は3次スプライン、設定かOキーで直線に切り替え（`replaymod_docs` 3.3.3.1）。CMDCamは linear・cosine・cubic・hermite・circular から選び、既定はエルミート（`cmdcam_modrinth`「hermite interpolation is default」）。FlashbackにはSmooth・Linear・Hermiteがある（`flashback_changelog` 0.9.0、0.16.0、0.30.0）。CineCamはSMOOTH／LINEAR／SPLINE（Catmull-Rom）。Cinemalyaは2点ならベジェ、3点以上ならCatmull-Rom（`cinemalya_modrinth`）。
- 使い分け【未確認】: 曲線は点を通るときに折れない。直線は点で向きが折れるが、経路が予測どおりになる。真横にまっすぐ動かすだけなら2点の直線で足りる。

### [CW-10] カメラの速さは「キーフレーム間の距離 ÷ キーフレーム間の時間」で決まる。等速にしたければ時間の間隔を距離に比例させる
- mc_version: ReplayMod、CMDCam、Cinemalya（26.2〜26.3）
- 確度: 【一次】
- 根拠: `replaymod_docs` 3.3.2「If two Keyframes are 5 seconds apart, the Camera Path will take 5 seconds to interpolate between those Keyframes」。CMDCamの `/cam distance_timing`「Can be used to make camera go with constant speed」。Cinemalyaは時間を指定しないウェイポイントの時間を区間の長さに比例して割り振り「one steady speed」にする。
- 落とし穴: 手で置いたキーフレームは時間の間隔が距離に比例しないので、途中で速くなったり遅くなったりする。

### [CW-11] 動き出しと止まり際の速さの変え方（イージング）を選べる
- mc_version: Cinemalya（26.2〜26.3）、CineCam（26.1.2）、CMDCam
- 確度: 【一次】
- 根拠: Cinemalyaの `ease` は linear／ease_in／ease_out／ease_in_out。経路全体にかけると「最初の点から加速し、中間は一定、最後に落ち着く」。CineCamのSMOOTHは「soft acceleration and deceleration」、LINEARは「constant movement speed」。CMDCamの `/cam smooth_start`。
- 参考【二次】: 統合版の `/camera` はイージングが32種類ある（`wiki_camera_cmd`）。Java版にこのコマンドはない。
- 使い分け【未確認】: 止まった状態から始まって止まって終わるショットは ease_in_out。前後を別のショットにつなぐ（動いたまま切る）ならlinear。

### [CW-12] スプラインは置いた点を全部なめらかに通るので、経路を目で見て確認する機能を使う
- mc_version: ReplayMod、Flashback、CMDCam、CineCam
- 確度: 【一次】（確認機能があること）／【二次】（膨らみやループが出ること）
- 根拠: ReplayModはHキーで経路を赤い線で表示（`replaymod_docs` 3.3.3.2）。Flashbackは「Visualize your camera path in 3D」。CMDCamは `/cam show`。CineCamは経路を青、視線を橙の線で表示。
- 【二次】: 点が近いと経路が妙なループや揺れになる、動かないはずの区間でカメラが少し動く、という報告がReplayModのフォーラムにあった（`web_replaymod_forum_search`。元のスレッドは現在404で、検索の要約でしか読めていない）。

### [CW-13] 回転の補間には固有の落とし穴がある（360°またぎの遠回り、真上・真下付近）
- mc_version: CMDCam（1.18.2〜26.3）、Flashback（0.8.0 より前）
- 確度: 【一次】（道具側に対策や修正があること）
- 根拠: CMDCamの `/cam spinning_fix` は「点の間の360°回転を無視して近い方向に回る／元の回転方向を保つ／補正しない」を選ぶ設定。Flashback 0.8.0「Fixed camera rotation issues when pitch is near 90 degrees」、0.19.0「Fixed camera rotation interpolation being incorrect when mixing interpolation types」。
- 対策【未確認】: 向きが180°以上変わる区間は中間にキーフレームを置く。真下・真上は89°程度で止める。補間の種類を1つの経路の中で混ぜない。

### [CW-14] 一瞬で切り替える（カット）には、ショットごとに分けて書き出すか、補間を止める設定を使う
- mc_version: Flashback、CineCam
- 確度: 【一次】（シーンの切り替え、CUT）／【二次】（Hold補間）
- 根拠: Flashback 0.13.0「Added scene switcher to make creating multiple shots from a single replay easier」。CineCamのCUT「an instant cut after the Hold time」。Flashbackでは補間をHoldにするか別々に書き出す、という説明（`web_flashback_hold_search`、検索の要約）。
- このチャンネルでは: ショットごとに別ファイルで書き出して、つなぐのは movie 側、が素直（`experiment.yaml` の `shots` が1ショット1件なのと合う）。

## 5. 時間の操作

### [CW-15] カメラの時間（動画の時間）と世界の時間（リプレイの時間）は、別々のキーフレームで制御する
- mc_version: ReplayMod
- 確度: 【一次】
- 根拠: `replaymod_docs` 3.3.2「the Keyframe Timeline's time values are not relative to the Replay's point of time, but refer to real time」、3.3.4「Every Time Keyframe represents a timestamp in the Replay itself」。

### [CW-16] スローと早送りは「世界の時間 ÷ 動画の時間」の比で決まる
- mc_version: ReplayMod、Flashback
- 確度: 【一次】
- 根拠: ReplayModでは、Time Keyframe の間でリプレイの時間が補間される（3.3.4）。再生速度のスライダーは0.1倍〜8倍（3.2.1）。FlashbackにはSpeedキーフレームがある（`flashback_changelog` 0.2.0、0.13.0）。
- 例: 世界の1秒（20tick）を動画の4秒にすれば0.25倍速。

### [CW-17] 世界の時間を止めたまま、カメラだけを動かせる（時間停止ショット）
- mc_version: ReplayMod、Flashback 0.14.0〜
- 確度: 【一次】
- 根拠: `replaymod_docs` 3.3.4「Two Time Keyframes with the same Timestamp will freeze the Replay time for the duration of their interval」。再生を一時停止した状態でも飛び回れる（3.2.1）。Flashback 0.14.0「Added Freeze keyframe」。

### [CW-18] ReplayModのカメラパスでは、世界の時間を巻き戻せない
- mc_version: ReplayMod
- 確度: 【一次】
- 根拠: `replaymod_docs` 3.3.4「Travelling backwards in time is not supported during Camera Paths」。
- 補足【二次】: 逆再生のタイムラプスを作る解説動画はある（`yt_0pZ8MaWH-PQ` の題名）。編集で逆再生しているのか、別の方法かは未確認。

### [CW-19] Flashback 0.33.0 以降、カメラの補間は実時間基準なので、途中で再生速度を変えてもカメラの動きは変わらない
- mc_version: Flashback 0.33.0〜
- 確度: 【一次】
- 根拠: `flashback_changelog` 0.33.0「Interpolation for non-time keyframes now uses realtime instead of ticks … if you modify the speed of the replay in the middle of a camera movement, the camera movement itself won't speed up or slow down」。以前の挙動（tick基準）はPreferencesで戻せる。
- 意味: 「通常速度 → 着地の瞬間だけスロー → 通常速度」のような速度の切り替えをしても、カメラは一定の速さで動き続ける。

### [CW-20] バニラの `/tick` でも世界の速さを変えられる（rate・freeze・step・sprint）
- mc_version: Java 1.20.3〜
- 確度: 【二次】
- 根拠: `wiki_tick_cmd`。`tick rate` は1.0〜10000 TPS（既定20）。`tick freeze` 中も「プレイヤーと、プレイヤーが乗っているエンティティ」は動く。コマンドブロックからは実行できない。
- このリポジトリとの関係: 計測は `tick freeze` と `tick step` のコマ送りで行っている（`lab/runner.py`）。世界を止めたままプレイヤー（カメラ役）は動けるので、録画しながらの時間停止ショットにも使える可能性がある。P2で確かめる。

### [CW-21] 長い時間を短く見せるタイムラプスは、専用のキーフレームで作れる
- mc_version: Flashback 0.2.0〜
- 確度: 【一次】
- 根拠: `flashback_changelog` 0.2.0、0.3.0「Made Timelapse keyframe easier to understand and use」。ReplayModでは Time Keyframe の間隔で同じことができる（[CW-16]）。
- 使いどころ: 実験装置を組み立てる過程。

## 6. 被写体を追う

### [CW-22] 追い方は3種類ある:(a) 乗り移る（主観）、(b) 位置を追う、(c) 向きだけ追う
- mc_version: 下の各道具
- 確度: 【一次】（各機能があること）
- 根拠:
  - (a) ReplayModのSpectator Keyframe（同じエンティティで2つ以上必要。`replaymod_docs` 3.3.5）。バニラのスペクテイターモードは攻撃ボタンでエンティティの視点に入れる（`wiki_spectator`【二次】）。
  - (b) CMDCamの `/cam follow`（位置を追う）。
  - (c) CMDCamの `/cam target`（向きを追う）、CineCamのTrack、Flashback 0.32.0 の「Track Entity」キーフレーム。
- 注意: ReplayModの説明は「You can spectate any **living** entitiy」（3.1.3）。落下中のブロックやアイテムは生物ではないので、ReplayModで乗り移れるかは【未確認】。バニラのスペクテイターは着火したTNTや防具立てにも入れるとWikiにある【二次】。
- FlashbackのTrack Entityが(b)と(c)のどちらの動きをするかは【未確認】（作者の解説動画 `yt_2adv42iyTC8` がある）。

### [CW-23] 追従には「なめらかさ」の設定があり、なめらかにするほど反応が遅くなる
- mc_version: CMDCam、CineCam
- 確度: 【一次】（設定の意味）／【未確認】（画への影響）
- 根拠: CMDCamの `/cam pitch step`・`yaw step`・`pos step`「1 is instant, the higher the value the slower it will be. Default is 20」。CineCamの「Track smoothing」。
- 推論【未確認】: なめらかにした追従カメラは速い被写体から遅れる。遅れた分だけ被写体が画面内を動くので、「画面内の動き」から速さを読ませるショットには使わない（§12）。

## 7. 画角・距離・構図の計算

### [CW-24] 距離 d から見える範囲は、縦 H = 2·d·tan(FOV/2)、横 W = H × アスペクト比
- mc_version: Java版
- 確度: 【未確認】（標準的な透視投影の式。FOVが縦の視野角であることは [CW-06]【二次】。MCで式どおりになるかはP2で実測）
- 根拠: 幾何。横の視野角を計算した結果がWikiの表（16:9）と一致することは確認した。

| FOV | 縦 H/d | 横 W/d（16:9） | 横 W/d（9:16） | 横の視野角（16:9） | 横の視野角（9:16） |
|---|---|---|---|---|---|
| 30 | 0.54 | 0.95 | 0.30 | 50.9° | 17.1° |
| 50 | 0.93 | 1.66 | 0.52 | 79.3° | 29.4° |
| 70（標準） | 1.40 | 2.49 | 0.79 | 102.4° | 43.0° |
| 90 | 2.00 | 3.56 | 1.13 | 121.3° | 58.7° |
| 110 | 2.86 | 5.08 | 1.61 | 137.0° | 77.6° |

- 読み方: FOV 70 で30ブロック離れると、縦は 1.40 × 30 = 42ブロック分、横は16:9で約75ブロック分、9:16で約24ブロック分が映る。
- 逆算: 高さ H を画面に収めるのに必要な距離は d = H ÷ (2·tan(FOV/2))。

### [CW-25] 縦動画（9:16）は、同じFOVと距離で、横に映る範囲が16:9の約3分の1になる
- mc_version: Java版
- 確度: 【未確認】（[CW-24] の式から。(9/16) ÷ (16/9) = 0.32）
- 意味: 落下のような縦の動きは縦動画に収まりやすい。横に並べて比べる画は入りにくいので、並べる間隔を詰めるか、離れるか、FOVを上げる。切り抜きではなく撮り直す方針（`docs/チャンネルコンセプト.md` §5）の理由にもなる。

### 計測ショットと演出ショットを分ける

- **計測ショット** = 数字やグラフの根拠として見せる画。視聴者が画面上の動きから速さや距離を読み取れることが目的。
  - カメラは固定する（[CW-23] の遅れを避ける）。
  - 真横（または真上）から、被写体を視線に垂直な1つの面に並べる（[CW-26]）。
  - 正投影が使えるなら使う（[CW-27]）。使えないなら低いFOVで遠くから撮る（[CW-28]）。
  - 目盛りは被写体と同じ面に置く。
  - スローにするなら倍率を画面に出す。
- **演出ショット** = 現象の迫力や規模を伝える画。追従、周回、寄り、スロー、時間停止など自由に使う。
- 同じ現象を、計測ショット1つと演出ショット数個で撮る。リプレイ方式なら記録は1回で済む（[CW-02]）。

### 目的からショットを選ぶ

`camera_moves.yaml` の `id` で書く。

| 見せたいこと | 第一候補 | 併用 |
|---|---|---|
| 装置の全体像・規模 | `establishing_wide` | `orbit`、`crane_reveal` |
| 2つ以上の物の速さの違い | `static_side`（計測ショット） | `follow`（片方に付いて、もう片方が離れていくのを見せる） |
| 一瞬の出来事（着地、衝突、爆発） | `slow_motion` ＋ `static_close` | `freeze_orbit`、`speed_ramp` |
| 長い距離の移動（高所からの落下） | `follow` | `pov`、縦動画 |
| 軌道の形（放物線など） | `static_side` | `top_down`（水平面内の動き） |
| 装置を作る過程 | `timelapse` | `flythrough` |
| 結果の数字を読ませる | `freeze_orbit` か静止画に、グラフを重ねる | — |

### E001 の `shots` を当てはめて点検した結果

`experiments/E001_free_fall/experiment.yaml`（雛形・未実行）に上の決まりを当てはめると、直したほうがよい点が2つある。**yaml は変更していない。** 関門2の前に検討する。

1. `wide_side` と `short_vertical` は、カメラがx軸上にあってx方向を見ている。一方、3つの被写体は `spacing: [4, 0, 0]` でx方向に並ぶ。**視線の方向に並ぶので重なって映る**（[CW-26]）。カメラをz側に置く（例: `pos: [4, 128, 30]`、`look_at: [4, 128, 0]`）か、被写体をz方向に並べる。
2. `wide_side` は距離30・FOV 70なら縦42ブロック分しか映らない（[CW-24]）。落下は256ブロックなので、全体は入らない。全体を入れるには約183ブロック離れる必要があり、エンティティの描画距離（[CW-29]）に触れる。長い落下は `follow` で見せ、引きの計測ショットは落下距離を短くした別テイク（例: 32ブロック）にする案がある。

### P2（撮影方式の比較）への材料

- 半自動（Flashbackで収録し、カメラは手で付ける）の側には、追尾・周回・時間停止・正投影・PNG連番・縦枠の確認まで、必要な機能がすでにある（`撮影ツール.md`）。
- 全自動の側の候補が、自作modのほかに3つ見つかった。CMDCam（コマンドで経路を定義。録画は外部ソフト）、Cinemalya方式（バニラのデータパック。RCONからも呼べる形）、CineCam（シーンがJSONファイル）。いずれも【未確認】で、P2で小さく試す価値がある。
