# ワールド内の演出（表示エンティティ・パーティクル・発光・画面表示）

> 対象: 撮影する映像の中に、文字・目印・軌跡・数値を出すバニラの仕組み。表示エンティティ（text_display / block_display / item_display）、/particle（dust の色、軌跡）、発光エフェクトとチームの色、名札、ボスバー、タイトル・アクションバー、スコアボードのサイドバー、テキストコンポーネント（/tellraw 等）。
> 使う場面: 実験の設計（`experiments/*/experiment.yaml` に演出のコマンドを書くとき）と撮影の準備。
> 調査日: 2026-11-19 ／ mc_version: Java Edition。表示エンティティは 1.19.4 以降、/particle の SNBT 書式は 1.20.5 以降、テキストの SNBT 書式は 1.21.5 以降。minecraft.wiki の記述は 2026-11-19 取得時点のもの（26.x 系の記述を含む）。統合版（Bedrock）は扱わない。
> 関連: [時間制御とスロー.md](時間制御とスロー.md), [ReplayMod.md](ReplayMod.md), [Flashback.md](Flashback.md), [カメラワーク技法.md](カメラワーク技法.md), [../mods/計測と可視化のmod.md](../mods/計測と可視化のmod.md), [../mods/Carpet.md](../mods/Carpet.md)

## 要点
- 表示エンティティ（block_display / item_display / text_display）は Java Edition 1.19.4（23w06a）で追加された。動かず、当たり判定も衝突もなく、プレイヤーや他のエンティティを押しのけない。【二次】[S1]
- 表示エンティティの見た目の変形（transformation）や一部の値は、tick 単位の時間をかけて補間（なめらかに変化）させられる。移動（テレポート）の補間は 1.20.2（23w31a）から teleport_duration で指定でき、0〜59 tick に制限される。【二次】[S1][S2]
- 表示エンティティは view_range × entityDistanceScaling（options.txt の設定）× 64 ブロックより遠いと描画されない。既定はどちらも 1.0 なので、既定では 64 ブロック（計算）。【二次】[S2][S14]
- テキスト表示は片面からしか見えない。billboard で常にカメラを向かせられる。テキスト表示には発光（Glowing）が効かない。【二次】[S1][S2]
- /particle は normal モードでは 32 ブロック未満のプレイヤーにしか送られず、ビデオ設定の『パーティクル』が最小だと出ないことがある。force モードなら 512 ブロック未満まで送られ、設定に関係なく表示される。【二次】[S3]
- dust の色は 0〜1 の RGB 3つ（または RGB を詰めた整数）で、大きさ scale は 0.01〜4。寿命は 8〜40 tick の乱数 × scale なので、dust で描いた軌跡は長くても数秒で消える。【二次】[S4]
- 1.21.4 で、目標の座標へ指定 tick で飛んでいく trail パーティクルが追加された（色は RGB 整数）。【二次】[S4]
- 発光（Glowing）は壁越しにも輪郭を見せる。色は既定で白、チームに入れるとチームの色になる。チームの色はテキストの色の名前（16 色）か reset だけで、16 進の色は使えない。表示エンティティなら glow_color_override で任意の色にできる。【二次】[S5][S6][S10][S2]
- チームの collisionRule を never にすると、そのチームのエンティティはどのエンティティにも押されなくなる（既定は always）。【二次】[S6]
- タイトルの表示時間（fadeIn / stay / fadeOut）はサーバではなく各クライアントに送られて残り、ワールドやサーバをまたいで引き継がれる。既定は 10 / 70 / 20 tick。wiki はクライアントの再起動で戻ると書き、同じページで `title <targets> reset` でも既定に戻るとしている。【二次】[S8]
- スコアボードのサイドバーは上位 15 件まで。表示形式 numberformat は blank（数字を出さない）/ fixed / styled。wiki の履歴では 1.20.3（23w46a）で目的に format（表示形式）が加わった。スコアは 32 ビット整数。【二次】[S9]
- 1.21.5 からテキストコンポーネントは JSON ではなく SNBT で書く。text_display、名前、/tellraw、/title、/bossbar、/scoreboard、/team で共通の書式。【二次】[S10][S8]
- Replay Mod はレンダリング設定『Render Nametags』を外すと名札（防具立てやモブのものも）を消せる。Flashback 0.33.0 ではプレイヤーの右クリックメニューに『Hide Text Below Name』が加わった（名前の下の文字を隠す項目と読めるが、名札そのものを消すかは変更履歴からはわからない）。【一次】[S11][S12]

## 詳細

### 表示エンティティ（Display entities）

#### 共通の性質
表示エンティティには block_display（ブロック）、item_display（アイテム）、text_display（文字）の3種類があり、/summon か /execute summon でだけ作れる。【二次】[S1]
> 「Display entities are entities useful for map or data pack creators to display various things.」[S1]

マーカーと同じく、動かない・ダメージを受けない・音を出さない・衝突しない。ブロックの設置を妨げず、プレイヤーや他のエンティティを押しのけない。【二次】[S1]
> 「Much like markers, display entities do not move, do not take damage, do not make sounds, and have no collision.」[S1]

マーカーと違ってクライアントに送られて描画され、デバッグ画面の E 値（エンティティ数）に数えられる。当たり判定（ヒットボックス）はなく、F3 + B でも表示されない。【二次】[S1]
> 「Unlike markers, display entities are sent to the client for rendering and do count toward in the E value (total amount of entities) listed on the debug screen.」[S1]

読み込まれた最初の 1 tick は必ず見えないので、召喚した直後に値を変えても、変える前の状態が一瞬映ることはない。【二次】[S1]
> 「display entities are always invisible for one tick when they are loaded.」[S1]

追加と主な変更（Java Edition）【二次】[S1]:

| バージョン | 変更 |
|---|---|
| 1.19.4（23w06a） | Block Display、Item Display、Text Display を追加 |
| 1.19.4 Release Candidate 1 | interpolation_start を start_interpolation に置き換え（意味も変わった）。start_interpolation はエンティティのデータに保存されない |
| 1.20（23w12a） | interpolation_duration が 0 なら前の値を必ず捨てる。最初のデータを受け取るまで描画しない |
| 1.20.2（23w31a） | クライアント側の位置と向きが、更新の次の tick から teleport_duration の長さで補間されるようになった（サーバ側の位置は即座に変わる） |

> 「Display entities now start updating their client-side position and rotation on the first tick after an update.」[S1]

#### 全種類に共通の主な NBT
いずれも 2026-11-19 取得時点の wiki の記述。【二次】[S2]

| タグ | 内容 | 既定 |
|---|---|---|
| billboard | カメラの方を向くか。fixed（固定）/ vertical（縦軸で回る）/ horizontal（横軸で回る）/ center（中心で回る） | fixed |
| brightness | 描画に使う明るさを上書きする。block と sky をそれぞれ 0〜15 で指定 | なし（その場の明るさ） |
| glow_color_override | 発光の輪郭の色を上書きする整数。-1 ならチームの色 | -1 |
| view_range | 描画される最大距離の係数 | 1.0 |
| width / height | 描画の切り捨て（カリング）に使う大きさ。0 なら切り捨てない | 0 |
| interpolation_duration | 補間にかける tick 数 | — |
| start_interpolation | 補間を始めるまでの遅れ（保存されない。コマンドで指定） | — |
| teleport_duration | テレポートの補間の tick 数。0〜59 に制限 | — |
| shadow_radius / shadow_strength | 影の半径（64 で頭打ち、0 以下で影なし）と濃さ | 0 / 1 |
| transformation | 描画の変形。分解形（right_rotation → scale → left_rotation → translation の順に適用）か、16 要素の行列形 | 変形なし |

> 「When the distance is more than <view_range>×<options.txt|entityDistanceScaling>×64, the entity is not rendered.」[S2]

entityDistanceScaling は options.txt（Java Edition）の項目で、エンティティを描画する最大距離の設定。範囲 0.5〜5.0、既定 1.0、20w17a（1.16）で追加。【二次】[S14]
> 「The maximum distance from the player that entities render」[S14]
> 「Values are clamped between 0 and 59 (inclusive).」[S2]
> 「Glowing does not work on text displays.」[S2]

回転は四元数（実部が最後の 4 要素）か、angle（ラジアン）と axis の組で書ける。保存されるときは四元数になる。【二次】[S2]

#### 種類ごとの性質
- **block_display**: block_state で指定したブロックのモデルを表示する。エンドゲートウェイやシュルカーボックスのように特別な描画を使うブロックがあり、流体は表示されない。変形の回転の中心はブロックモデルの下・北・西の角。【二次】[S1]
> 「The rotation pivot of the block display's transformation is the bottom-north-west corner of the block model.」[S1]
- **item_display**: item のアイテムのモデルを表示する。item_display タグで、手に持ったとき・頭・GUI・地面などのどの表示用の変形を使うかを選べる（既定 none）。回転の中心はモデルの中心。/item と /loot で中身を差し替えられる。【二次】[S1]
- **text_display**: text タグのテキストコンポーネントを表示する。文字は片面からしか見えず、複数行なら上に伸びる。回転の中心は文字の下端の中央。既定では文字の 1 ピクセルが 1/40 m。【二次】[S1]
> 「By default, each pixel of text is 1/40th of a meter wide.」[S1]

text_display 固有のタグ【二次】[S1]:

| タグ | 内容 | 既定 |
|---|---|---|
| alignment | center / left / right | center |
| background | 背景色（ARGB の整数）。A が 26（0x1A）未満だと完全に透明になる。補間される | 1073741824（0x40000000） |
| default_background | true ならチャットと同じ背景色を使う | false |
| line_width | 折り返しの最大幅（\n でも改行できる） | 200 |
| see_through | ブロック越しに見えるか | false |
| shadow | 文字に影を付けるか | false |
| text_opacity | 文字の不透明度 0〜255（3 以下は不透明扱い、4〜26 は描画されない）。補間される | -1（=255） |

#### 補間（なめらかな変化）
wiki の Entity data で Interpolated と書かれた値（transformation、background、text_opacity、shadow_radius、shadow_strength など）は、まとめて補間される。補間は start_interpolation から start_interpolation + interpolation_duration（tick）の間に進む。【二次】[S1][S2]

サーバはクライアントへエンティティの状態を 1 tick に最大 1 回しか送らないので、同じ tick 内に何回変えても 1 回の変化として扱われる。【二次】[S1]
> 「Since server synchronizes entities with the client at most once per game tick, multiple changes within one game tick still count as a single change.」[S1]

補間が決定的かどうかについてのバグ報告（MC-259926、原文未読）は「わかっていないこと・要確認」に書いた。

### パーティクル（/particle）
書式（Java Edition）【二次】[S3]:
```
particle <name> [<pos>]
particle <name> <pos> <delta> <speed> <count> [force|normal] [<viewers>]
```
- **count が 0 のとき**: pos にちょうど 1 個出し、delta × speed をパーティクルの引数として渡す。多くのパーティクルでは delta が動く向き（速度）になる。【二次】[S3]
- **count が 0 でないとき**: pos を平均、delta を標準偏差とする正規分布の位置に count 個出す。【二次】[S3]
- **表示の距離**: normal は 32.0 ブロック未満のプレイヤーにだけ送られ、ビデオ設定の『パーティクル』が「最小」だと出ないことがある。force は 512.0 ブロック未満まで送られ、「最小」でも必ず表示される。既定は normal。【二次】[S3]
> 「force: Allows the particle(s) to be sent to players within 512.0 blocks (exclusive). Always shown even if the "Particles" option in Video Settings is "Minimal".」[S3]
- **viewers**: 見せるプレイヤーを限定できる。【二次】[S3]
- **書式の変更**: 1.20.5 Pre-Release 1 から、/particle のパーティクルの設定はワールド生成のファイルと同じ SNBT 形式で書く（例: `dust{color:[1, 0, 1], scale:4}`）。それより前の書式はこの調査では確認していない。【二次】[S3][S4]
- /particle の権限レベルは Java Edition で 2。【二次】[S3]

wiki の例（紫の大きな dust を 10 個）【二次】[S3]:
```
/particle minecraft:dust{color:[1, 0, 1], scale:4} ~ ~ ~ 1 1 1 1 10
```

#### 色を指定できるパーティクル（Particle format）
2026-11-19 取得時点の wiki の記述。【二次】[S4]

| 種類 | 主な設定 |
|---|---|
| dust | color（0〜1 の RGB 3 つ、または RGB を詰めた整数）、scale |
| dust_color_transition | from_color → to_color（0〜1 の RGB）、scale。範囲外の値は未定義の動作 |
| entity_effect / flash | color（RGBA の 4 つの小数、または ARGB 整数）。1.21.9（25w36a）から flash は color が必須 |
| effect / instant_effect | 1.21.9（25w36a）から power と color を任意で指定できる |
| trail | target（向かう座標）、color（RGB 整数）、duration（到達までの tick 数）。1.21.4 で追加 |
| vibration | destination（ブロック座標）、arrival_in_ticks |
| block / falling_dust / dust_pillar 等 | block_state |

> 「Three floats representing the red, green, and blue components of the dust color. Each value must be between 0 and 1. Can alternatively be an rgb packed integer.」[S4]
> 「The particle's lifetime is a random integer from 8 to 40 game ticks, then multiplied by this scale value, with a minimum of 0.01 and a maximum of 4.」[S4]

dust の寿命は 8〜40 tick の乱数に scale（0.01〜4）を掛けたものなので、最大でも 160 tick（20 TPS で 8 秒）。寿命に乱数が入るので、同じ時刻に出した点でも消える時刻はそろわない。【二次】[S4]（160 tick は上の記述からの計算）

### 発光（Glowing）とチームの色
- 発光はステータス効果で、エンティティの輪郭を、ブロックや他のエンティティ越しにも見せる。Java Edition 1.9（15w31a）で追加。【二次】[S5]
> 「Glowing causes entities to glow with an outline that can be seen through blocks and entities.」[S5]
- 輪郭は既定で白。チームに入っていればチームの色になる。近くにある複数の発光エンティティの輪郭はつながって 1 つになる。【二次】[S5]
> 「If multiple entities with glowing are near each other, the outlines merge to prevent overlapping/z-fighting.」[S5]
- ウィザーとエンダードラゴンには効かない。【二次】[S5]
- チームの color は、チャット・頭上の名前・Tab の一覧・サイドバーでの色と、発光の輪郭の色を決める。指定できるのはテキストの色の名前（と reset）で、16 進の色コードは使えない。【二次】[S6]
> 「Must be a text color except for hexadecimal color codes.」[S6]
- 表示エンティティは glow_color_override（整数）で任意の色の輪郭にできる（-1 ならチームの色）。ただしテキスト表示には発光が効かない。【二次】[S2]
- チームのその他の設定: nametagVisibility（never / hideForOtherTeams / hideForOwnTeam / always）、collisionRule、prefix / suffix（テキストコンポーネント）。【二次】[S6]
> 「never - No entities can push the entities in this team.」[S6]

### 名札（頭上の名前）
- 名前の表示はチームの nametagVisibility で、never（誰にも見えない）から always（既定）まで切り替えられる。【二次】[S6]
- Replay Mod は、レンダリングの詳細設定『Render Nametags』のチェックを外すと名札を消せる。プレイヤーだけでなく防具立てやモブの名札も消える。【一次】[S11]
> 「Hidden Nametags also include Nametags of Armor Stands and Mobs, not only Players!」[S11]
- Flashback 0.33.0（Modrinth の表示では MC Java Edition 1.21.5 向け）で、プレイヤーの右クリックメニューに『Hide Text Below Name』のチェックボックスが追加された。変更履歴にあるのはこの1行だけで、名札そのもの（名前）を消す項目なのか、名前の下の文字（スコアボードの below_name など）だけを隠す項目なのかは書かれていない。【一次】[S12]
> 「Added 'Hide Text Below Name' checkbox to player right-click menu」[S12]

### ボスバー（/bossbar）
- Java Edition 1.13（18w05a）で追加。作ったボスバーは level.dat の CustomBossEvents に保存される。【二次】[S7]
> 「Create a new bossbar (stored in level.dat CustomBossEvents).」[S7]
- 設定: color（blue / green / pink / purple / red / white / yellow、既定 white）、max（既定 100、1 以上の整数）、value（既定 0、0 以上の整数）、style（progress / notched_6 / notched_10 / notched_12 / notched_20、既定 progress）、name（テキストコンポーネント）、players、visible。【二次】[S7]
- 作った直後は誰にも見えない。players で見せるプレイヤーを指定する必要がある。【二次】[S7]
> 「If not specified, the boss bar is invisible to any player.」[S7]
- 1.21.5（25w05a）から、テキストコンポーネントの引数は @s のエンティティの文脈で解決される。【二次】[S7]

### タイトル・サブタイトル・アクションバー（/title）
書式（Java Edition）【二次】[S8]:
```
title <targets> (clear|reset)
title <targets> (title|subtitle|actionbar) <title>
title <targets> times <fadeIn> <stay> <fadeOut>
```
- タイトルは画面中央の大きな 1 行、サブタイトルはその下の 1 行、アクションバーはホットバーのすぐ上。どれもテキストコンポーネントで書く。【二次】[S8]
- タイトルは GUI の大きさに合わせて大きさが変わり、画面に収まらなくても折り返されずに左右へはみ出す。【二次】[S8]
> 「screen titles that are too big to fit on the screen are not line-wrapped (they just overflow off the screen on both sides).」[S8]
- fadeIn / stay / fadeOut はサーバではなく各クライアントに送られて残り、ワールドやサーバをまたいで引き継がれる。wiki はクライアントの再起動でだけ戻ると書いているが、同じページの reset の説明では、`title <targets> reset` でもサブタイトルと表示時間が既定（10 / 70 / 20 gt）に戻る。【二次】[S8]
> 「These values are reset only when the client restarts, and the default is 10 game ticks (0.5 seconds), 70 game ticks (3.5 seconds), and 20 game ticks (1 second).」[S8]
> 「Resets the subtitle text for the specified player(s) to blank text, and the fade-in, stay and fade-out times to their default values」[S8]
- Java Edition の fadeIn / stay / fadeOut は time 型（単位 d / s / t を付けられる単精度の数）。wiki の履歴では、それ以前は整数の tick だった。【二次】[S8]
- subtitle は、タイトルが表示中ならその場で変わり、表示中でなければ次のタイトルのサブタイトルとして予約される。title はフェードアウトのあとサブタイトルを空に戻すが、時間の設定は戻さない。【二次】[S8]
- 履歴: /title は 1.8（14w20a）で追加、アクションバーへの表示は 1.11（16w32b）で追加、1.21.5（25w02a）からテキストコンポーネントは JSON ではなく SNBT。【二次】[S8]

### スコアボードのサイドバー
- サイドバーは画面右側に、その目的（objective）のスコアが高い順に最大 15 件を、表示名を見出しにして出す。【二次】[S9]
> 「Shows on the right hand side of the screen, up to 15 entities with the highest score of that objective with a heading labeled with the objective's display name.」[S9]
- 名前が # で始まる偽のプレイヤー（スコアの保持者）はサイドバーに出ない。【二次】[S9]
> 「fake players with names starting with a # character do not show up in the sidebar under any circumstances.」[S9]
- プレイヤー以外のエンティティのスコアを出せるのはサイドバーだけ（他の表示枠はプレイヤー専用）。チームの色ごとのサイドバー（sidebar.team.<color>、16 枠）もある。【二次】[S9]
- below_name（頭上の名前の下）は約 10 ブロックより遠いと隠れ、スニーク中も隠れ、シングルプレイでは見えない。【二次】[S9]
> 「This is hidden beyond around 10 blocks and when the player is sneaking. Not visible in singleplayer.」[S9]
- 表示形式 numberformat: blank（数字を出さない）、fixed（指定した内容を出す）、styled（色などを付けて数字を出す）。/scoreboard players display numberformat|name で保持者ごとに数字の形式や表示名を変えられる。1.20.3（23w46a）で目的に format と display_auto_update、保持者に display が加わった。【二次】[S9]
> 「blank displays nothing on the scoreboard.」[S9]
- スコアの値は 32 ビット整数（-2,147,483,648〜2,147,483,647）。【二次】[S9]

### テキストコンポーネントと /tellraw
- 1.21.5 からテキストコンポーネントは SNBT で書く（例: `{text: "Hello world"}`）。1.21.5 より前の JSON 形式は wiki の別ページ。【二次】[S10]
> 「They are used for rich text formatting in written books, signs, text displays, custom names and the /tellraw, /title, /bossbar, /scoreboard and /team commands.」[S10]
- color は 16 進（"#RRGGBB" の 6 桁）か色の名前。shadow_color で影の色と不透明度も指定できる。【二次】[S10]
- 中身の種類: text、translatable、score（スコアボードの値）、selector、keybind、nbt（エンティティ・ブロックエンティティ・ストレージの NBT）。【二次】[S10]
> 「Displays a score holder's current score in an objective.」[S10]
- nbt の中身は既定では SNBT としてキーや値に色が付いて表示される。plain を true にすると色が付かない。【二次】[S10]

## このチャンネルでの使い方（提案）
> ※この節は上の事実から導いた提案で、事実ではない。

- **実験の物理を乱さない目印は表示エンティティで作る。** 衝突も押し合いもないので、落下物の通り道に置いても結果を変えないはず。ただし E 値に数えられるので、大量に置くときは負荷を見る（根拠: [S1]）。本当に影響しないかは E001 などで、置いた場合と置かない場合の着地 tick を比べて【実測】にする。
- **引きの画では view_range を上げ、パーティクルは force で出す。** 既定のままだと、表示エンティティは 64 ブロック、パーティクルは 32 ブロックを超えると映らない。カメラが遠い空撮やタイムラプスでラベルが消える事故を防げる（根拠: [S2][S14][S3]）。録画用の設定でパーティクルを「最小」にしていても force なら出る（根拠: [S3]）。
- **軌跡は用途で描き分ける。** 数秒で消えてよい軌跡は dust（寿命が最大 160 tick・消える時刻はばらつく）、最後まで残す軌跡は小さく縮めた block_display を毎 tick 置く、2 点を結ぶ動きの演出は trail（1.21.4 以降）（根拠: [S4][S1][S2]）。`/tick freeze` と `step` で計測するときに毎 step で目印を置けば、等時間間隔の「ストロボ写真」になる（[時間制御とスロー.md](時間制御とスロー.md) と組み合わせる）。
- **数値のラベルは text_display の billboard: center + brightness 固定。** カメラの向きや昼夜・シェーダーで読めなくなるのを避ける（根拠: [S2]）。背景を消すなら background の A を 26 未満にする（根拠: [S1]）。
- **色分けは表示エンティティの glow_color_override を優先する。** チームの色は 16 色に限られ、collisionRule などの物理に関わる設定と同じ仕組みに乗るため（根拠: [S6][S2]）。チームを使う場合は collisionRule を既定（always）のままにしたことを experiment.yaml に書く（根拠: [S6]）。
- **計測値を画面に出すなら、映像の文字は編集（Remotion）で入れ、ワールド内の表示は「現場の目印」に絞る。** スコアは整数なので小数の速度は 1000 倍などにする必要があり、サイドバーは 15 件まで（根拠: [S9]）。ゲーム内の表示は録画 mod のカメラ位置によって大きさや向きが変わるが、編集で入れた文字は動かない。
- **タイトルの表示時間は毎回の撮影の最初に `title @a times ...` で明示する。** 設定がクライアントに残るため、前の撮影の値が持ち越される（根拠: [S8]）。
- **名札は、Replay Mod なら録画後に消せる。** 偽プレイヤー（Carpet の /player）の名前が映り込んでも、Replay Mod の『Render Nametags』を外せば書き出しで消える（根拠: [S11]）。Flashback の『Hide Text Below Name』は名札そのものを消す項目かどうかが不明なので、Flashback で撮る回はチームの nametagVisibility を never にしてから録る（根拠: [S6][S12]。Flashback 側で消せるかは試して【実測】にする）。
- **色分けにチームを使うときは、collisionRule に触れない。** never にすると押し合いがなくなり、実験の物理が変わる（根拠: [S6]）。
