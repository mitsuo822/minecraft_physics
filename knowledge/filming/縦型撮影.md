# 縦型（9:16）の撮影

> 対象: ショート用の 9:16（と 1:1）の映像を Minecraft Java版から作る方法。Replay Mod・Flashback の書き出し解像度と縦横比、ゲームのウィンドウ自体を縦にして撮る方法、縦構図での FOV、OBS の縦キャンバスを MC の撮影で使うかの判断。OBS の縦キャンバスのプラグインそのものの説明は movie の [画面録画とエンコード.md](https://github.com/mitsuo822/movie/blob/main/knowledge/editing/画面録画とエンコード.md) に任せる。ショートの UI で隠れる領域（セーフゾーン）の数値とショートの編集は M3 の [ショート編集.md](https://github.com/mitsuo822/movie/blob/main/knowledge/editing/ショート編集.md)（movie リポジトリ）に任せ、ここでは MC での撮り方に絞る。
> 使う場面: ショートの撮影計画を立てるとき。ショート用に 9:16 で撮り直す方法を選ぶとき（9:16 は切り抜きではなく撮り直す、というチャンネルの方針は [../../docs/チャンネルコンセプト.md](../../docs/チャンネルコンセプト.md) §5）。
> 調査日: 2026-11-19 ／ mc_version: Java Edition（Flashback は 1.21〜26.3 の版、options.txt の `overrideWidth` / `overrideHeight` は 1.4.6 から。Replay Mod のドキュメントの対象バージョンは不明）
> 関連: [../../docs/チャンネルコンセプト.md](../../docs/チャンネルコンセプト.md)（§5 ショートの方針）, [カメラワーク技法.md](カメラワーク技法.md), [ReplayMod.md](ReplayMod.md), [Flashback.md](Flashback.md), [録画設定.md](録画設定.md), [ショート編集.md](https://github.com/mitsuo822/movie/blob/main/knowledge/editing/ショート編集.md), [画面録画とエンコード.md（movie）](https://github.com/mitsuo822/movie/blob/main/knowledge/editing/画面録画とエンコード.md)

## 要点
- Replay Mod のレンダリングの解像度は、幅×高さを自由に入力できる（ドキュメントの例は 1280×720、1920×1080、3840×2160 の横長だけ）。【一次】[S1]
- Flashback の言語ファイルには縦横比（Aspect）の選択肢の表示名として『9:16 (Shorts)』と『1:1 (Square)』がある（取得: 2026-11-19。どの画面の項目かは言語ファイルからは読み取れない）。【一次】[S2]
- Flashback には構図のガイドとして『Rule of Thirds Guide』（三分割）と『Center Guide』（中央）がある。【一次】[S2]
- Flashback の書き出しには、UI を消す『No GUI』、空を透明にする『Transparent Sky』、深度を灰色で書き出す『Depth Map』、2倍の解像度で描いて縮める『SSAA』の項目がある。【一次】[S2]
- Flashback は全画面のまま書き出すと問題が起きるとして、書き出し前に全画面を切るよう表示する。【一次】[S2]
- Java版の FOV の設定値は縦の視野角で、横の視野角は画面の縦横比で変わる。FOV 70 の横の視野は 4:3 で 86.1°、16:9 で 102.4°（minecraft.wiki の表）。【二次】[S3]
- Java版の options.txt の `overrideWidth` / `overrideHeight` で、起動時のウィンドウの幅と高さを px で指定できる（1.4.6 から、ゲーム内に対応する設定はない）。【二次】[S4]
- 全画面の解像度（`fullscreenResolution`）はモニターが対応する値でなければならない。【二次】[S4]
- 選べる GUI の大きさの段階の数は画面の幅と高さで決まり、式は `max(1, min(floor(width / 320), floor(height / 240)))`。【二次】[S3]

## 詳細

### 1. 録画 mod から 9:16 で書き出す

**Replay Mod**
- 『Render Camera Path』から開くレンダリング設定で、描画方法（Default / Stereoscopic / Cubic / Equirectangular）を選び、その下に解像度（幅×高さ）を入力する。【一次】[S1]
  > 「You can enter any resolution there, but make sure to use reasonable values.」[S1]
- ドキュメントに挙がっている一般的な解像度は 720p（1280×720）、1080p（1920×1080）、4k（3840×2160）で、縦長の例はない。【一次】[S1]
- Equirectangular（360°）の書き出しは常に 2:1 が必要と書かれている。縦長にはできない。【一次】[S1]
- 解像度・エンコードの詳しい設定は [ReplayMod.md](ReplayMod.md)。

**Flashback**（master ブランチの言語ファイル、取得: 2026-11-19）
- 縦横比（Aspect）の選択肢の表示名は次の6つ。【一次】[S2]

| 表示名 | 縦横比 | 確度・出典 |
|---|---|---|
| 16:9 (HDTV) | 16:9 | 【一次】[S2] |
| 9:16 (Shorts) | 9:16 | 【一次】[S2] |
| 2.40:1 (Widescreen) | 2.40:1 | 【一次】[S2] |
| 1:1 (Square) | 1:1 | 【一次】[S2] |
| 4:3 (Fullscreen) | 4:3 | 【一次】[S2] |
| 3:2 (Photo) | 3:2 | 【一次】[S2] |

- 『Sizing』の項目として『Keep Aspect Ratio』『Change Aspect Ratio』『Fill』『Underlay』の表示名がある。それぞれの挙動は言語ファイルからは読み取れない。【一次】[S2]
- 構図のガイド『Rule of Thirds Guide』と『Center Guide』がある。【一次】[S2]
- 書き出しの画面には『Resolution』と『SSAA』がある。SSAA は2倍の解像度で描いてから縮めて、ギザギザを消す。【一次】[S2]
  > 「Supersampling Anti-Aliasing: Remove jagged edges by rendering the game at double resolution and downscaling」[S2]
- 『No GUI』は画面の UI をすべて消してワールドだけを描く。【一次】[S2]
  > 「Removes all UI from the screen, rendering only the world」[S2]
- 空を透明にして書き出すには、『Visuals』の窓で『Render Sky』を外してから、書き出しの窓で『Transparent Sky』を入れる。【一次】[S2]
  > 「Export with a transparent sky by first unticking 'Render Sky' in the Visuals window and then ticking 'Transparent Sky' in the export window」[S2]
- 『Depth Map』は深度を灰色の画像で書き出す。【一次】[S2]
- 『Export Screenshot』で静止画も書き出せる。【一次】[S2]
- 全画面のまま書き出すと問題が起きる。【一次】[S2]
  > 「Fullscreen causes various issues when exporting. Please disable fullscreen before exporting」[S2]
- 書き出しの範囲は I / O キーで決める。書き出しは『File』メニューの『Export Video』から。【一次】[S2]

### 2. ゲームのウィンドウを縦にして撮る（リアルタイム録画）

- Java版の options.txt で、起動時のウィンドウの大きさを指定できる。【二次】[S4]

| キー | 意味 | 既定 | 追加された版 | 確度・出典 |
|---|---|---|---|---|
| `overrideWidth` | 起動時のウィンドウの幅（px）。0 は既定の大きさ | 0 | Java 1.4.6 | 【二次】[S4] |
| `overrideHeight` | 起動時のウィンドウの高さ（px）。0 は既定の大きさ | 0 | Java 1.4.6 | 【二次】[S4] |
| `fullscreenResolution` | 全画面の解像度。`幅x高さ@リフレッシュレート:色ビット` の形式。モニターが対応しない値は「Current」に戻る | なし | 17w43a（1.13） | 【二次】[S4] |

  > 「Initial window width in pixels. A value of 0 uses the default. No in-game control.」[S4]
  > 「Values must be supported by the monitor.」[S4]
- GUI の大きさで選べる段階は解像度で決まる。【二次】[S3]
  - 式: `max(1, min(floor(width / 320), floor(height / 240)))`【二次】[S3]
- スペクテイターモードでは HUD は字幕とチャット以外表示されない（[カメラワーク技法.md](カメラワーク技法.md) の §7）。【二次】[S7]

### 3. 縦構図と FOV

- Java版の FOV の設定値は縦方向の視野角で、横の視野角は画面の縦横比で変わる。【二次】[S3]
  > 「In Minecraft, the FOV value represents how many degrees of vertical vision the player gets without modifying effects such as sprinting, flying or status effects.」[S3]
- minecraft.wiki の表（設定値＝縦の視野角 → 横の視野角）の一部。【二次】[S3]

| FOV の設定値（縦） | 横（4:3） | 横（16:9） | 確度・出典 |
|---|---|---|---|
| 30° | 39.3° | 50.9° | 【二次】[S3] |
| 50° | 63.7° | 79.3° | 【二次】[S3] |
| 70°（Normal、既定） | 86.1° | 102.4° | 【二次】[S3] |
| 90° | 106.3° | 121.3° | 【二次】[S3] |

- FOV の範囲は 30〜110、既定 70。【二次】[S4]
- ゲーム内の FOV・画面効果の設定は [録画設定.md](録画設定.md)、カメラの FOV のキーフレームは [カメラワーク技法.md](カメラワーク技法.md) の §4。

### 4. OBS の縦キャンバス

- OBS Studio に縦のキャンバスを追加するプラグインとして Aitum の『Vertical Canvas for OBS Studio』がある（README の冒頭）。【一次】[S5]　配布先と、機能の詳細・必要な OBS のバージョンが README になく検索要約でしか得られていない点は、movie の [画面録画とエンコード.md](https://github.com/mitsuo822/movie/blob/main/knowledge/editing/画面録画とエンコード.md) にまとめた。
- OBS の録画の設定（エンコーダ・形式）も同じ movie のファイル、ゲーム内の設定は [録画設定.md](録画設定.md)。

### 5. ショートの UI で隠れる領域

## このチャンネルでの使い方（提案）
> ※この節は上の事実から導いた提案で、事実ではない。下の角度・画素数は、出典の値と公式から自分たちで計算したもの（計算の結果で、MC 内での実測ではない）。

- **前提はチャンネルの方針: 9:16 の映像は切り抜きではなく撮り直す**（[../../docs/チャンネルコンセプト.md](../../docs/チャンネルコンセプト.md) §5）。下の提案はこの方針に合わせる。撮り直しの方法は2つ: (1) 実験を再実行して縦用のカメラで撮る、(2) 同じリプレイを縦用のカメラパスで描き直す。Replay Mod・Flashback のカメラパスは録画したリプレイの上で付けるので、乱数で毎回結果が変わる現象（[../../docs/MC実行基盤.md](../../docs/MC実行基盤.md) §5 では再実行で完全には一致しないものとして扱う）の見栄えのよい1回も、(2) なら縦で撮り直せる。（根拠: [S1][S2]、カメラパスの詳細は [ReplayMod.md](ReplayMod.md)・[Flashback.md](Flashback.md)）

- **縦の画角の計算。** minecraft.wiki の表の値は、横の視野角 = 2·atan(tan(縦の視野角/2)·縦横比) で再現できる（FOV 30/50/70/90 の 4:3・16:9 の値で検算して一致）。この式で 9:16 を計算すると、FOV 70 の横の視野は約 43.0°、FOV 110（最大）でも約 77.6°。16:9・FOV 70 と同じ横幅（102.4°）を 9:16 で入れるには縦の視野角が約 131° 必要で、FOV の上限 110 を超える。**横に広い実験はそのまま縦にすると収まらない**ので、カメラを引くか、縦に長い実験（落下、跳躍、積み上げ）を縦用に選ぶ。（根拠: [S3][S4]）
- **16:9 の 4K からの中央の切り抜きは、方針（撮り直し）の例外の予備にとどめる。** 使うのは、リプレイが残っていないリアルタイム録画の素材しかなく、再実行でも同じ場面を撮れないときだけ。3840×2160 から 9:16 を切ると 1215×2160 で、1080×1920 に縮められる。切り抜いた部分の横の視野は、9:16・FOV 70 で直接描いたときと同じ約 43.0° になる（計算）。（根拠: [S1][S3]）
- **ショート用のショットは Flashback の縦横比『9:16 (Shorts)』を選んで構図を作ることを試す。** それが表示の枠だけなのか、書き出しの解像度も縦にするのかは言語ファイルからわからないので、最初の試し撮りで確かめ、縦にならなければ『Resolution』に 1080×1920 を入れる。『Rule of Thirds Guide』『Center Guide』で被写体の位置を決め、UI で隠れる領域は M3 の数値に合わせて避ける。書き出しは『No GUI』、全画面は切る。（根拠: [S2]、セーフゾーンは [ショート編集.md](https://github.com/mitsuo822/movie/blob/main/knowledge/editing/ショート編集.md)）
- **Replay Mod なら解像度に 1080×1920 を直接入れて試す。** ドキュメントは縦長の例を挙げていないので、最初に短いパスで縦の書き出しが崩れないかを確かめる。（根拠: [S1]）
- **テロップを空に重ねる縦構図**では、Flashback の『Transparent Sky』で空を抜いて書き出し、Remotion で背景と文字を合成する方法がある。（根拠: [S2]）
- **リアルタイム録画（OBS）で縦にするなら**、options.txt の `overrideWidth` / `overrideHeight` で縦長のウィンドウにする。ただしウィンドウが 1080×1920 だと、選べる GUI の大きさの段階は min(floor(1080/320), floor(1920/240)) = 3 まで（計算）。HUD は F1 で消す前提にする。モニターより高いウィンドウを作れるかは未確認なので、まず Flashback / Replay Mod の書き出しを第一候補にする。（根拠: [S3][S4]）
- **OBS の縦キャンバスで1本の録画から横と縦を同時に作る方法は、基本の手段にしない。** 縦を横と同じカメラで撮ることになり、縦用のカメラ位置で撮り直すという方針に合わないため。Flashback・Replay Mod が使えない構成（例: [../mods/バージョン対応表.md](../mods/バージョン対応表.md) の B、1.21.1＋NeoForge）で、再実行で同じにならない現象をリアルタイム録画する回だけの予備にする。機能は検索要約でしか確かめていないので、使うなら配布ページと対応する OBS のバージョンを先に読む。（根拠: [S5]、機能と検索要約の内容は movie の [画面録画とエンコード.md](https://github.com/mitsuo822/movie/blob/main/knowledge/editing/画面録画とエンコード.md)）

## わかっていないこと・要確認
- Flashback の縦横比の選択肢（『9:16 (Shorts)』など）がどの画面の項目か。選んだとき、書き出しの解像度も自動で縦になるのか、編集画面の表示の枠だけなのか。『Sizing』の『Fill』『Underlay』の意味。
- Replay Mod で縦長（例: 1080×1920）を入れたとき、書き出しの映像が正しく縦になるか。ウィンドウより大きい解像度を描けるか。ドキュメントに記述がない。
- Windows で、モニター（このPCのモニターの解像度も未確認）より高い `overrideHeight` を指定したときにどうなるか。
- 平行投影（OrthoCamera の X / Y の縮尺、Flashback の『Orthographic』）を 9:16 で使ったときの縮尺の扱い。
- Aitum の縦キャンバスのプラグインの現行版の機能と、必要な OBS のバージョン（検索要約しか得られていない。内容は movie の [画面録画とエンコード.md](https://github.com/mitsuo822/movie/blob/main/knowledge/editing/画面録画とエンコード.md) の要確認の節）。
- ショートの UI で隠れる領域の数値（M3 で調べる）。
