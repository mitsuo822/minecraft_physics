## 使い方（ショットを設計するとき）

AIがこの知見を使って `experiment.yaml` の `shots` を書く・点検するときの手順。

1. **見せたいことを決める。** 「2つの速さの違い」「一瞬の出来事」「装置の規模」など。
2. **種類を選ぶ。** `カメラワーク.md` §12 の「目的からショットを選ぶ」の表で、`camera_moves.yaml` の `id` を選ぶ。大きさ（引き・寄り）と角度（真横・見上げ・見下ろし）は、同じファイルの `framing_terms` の用語で決める（`[CW-42]`）。
3. **計測ショットか演出ショットかを決める。** 数字の根拠として見せる画は `measurement: true` の種類から選び、カメラを固定する。
4. **量を決める。** その種類の `params` を埋める。距離とFOVは `[CW-24]` の式で計算する（見える縦の範囲 = 2 × 距離 × tan(FOV/2)）。
5. **点検する。**
   - 比べたい物を、視線の方向ではなく、視線と直角に並べているか（`[CW-26]`）。
   - 被写体が描画される距離に入っているか（`[CW-29]`）。
   - 16:9 と 9:16 で、見える横幅が約3倍違うことを織り込んだか（`[CW-25]`）。
   - その種類の `pitfalls` に当てはまらないか。
6. **`experiment.yaml` の `shots` に書く。** 撮影指示の正本はそちら。この目録に個別の実験の撮影指示は書かない。
7. **撮る道具での作り方を引く。** `how` の行を見る。`confidence: 未確認` や `二次` の行は、そのまま信じずに実機で確かめる。

### `shots` での書き方（提案。`docs/実験定義.md` はまだ変えていない）

今の `shots` は `camera: {pos, look_at}` と `{follow, offset}` だけを持つ。種類を明示する `move` と `fov` を足すと、この目録と対応が取れる。

```yaml
shots:
  - name: side_measure
    move: static_side            # camera_moves.yaml の id
    aspect: "16:9"
    camera: {pos: [4, 16, 40], look_at: [4, 16, 0], fov: 30}
    speed: 1.0
```

## 取得依頼（調査の続きを人に頼む）

クラウドのセッションからは、YouTubeの字幕・映像、Mojangのバグ票、modのソースコード、実機の画面が見られない。これらを人が保存し、あとでAIが読む、という流れを `requests/` に置いた。

| ファイル | 中身 |
|---|---|
| `requests/requests.yaml` | **正本。** 依頼の一覧。項目ごとに、優先度、保存先、知りたいこと（`look_for`）、解決したい項目（`resolves`）、状態（`status`） |
| `requests/取得依頼.html` | 人が開くページ（生成物）。リンクとチェック欄 |
| `requests/urls_A.txt`・`urls_B.txt`・`urls_C.txt` | 優先度ごとの動画URLの一覧（生成物）。一括ダウンロード用 |
| `requests/build.py` | 生成物を作り直す。`python knowledge/filming/requests/build.py` |

- 保存先は `media/research/camera/`（git の管理外）。**動画・字幕・保存したページはリポジトリに入れない。** 知見として自分たちの言葉でまとめたものだけを `knowledge/` に書く。
- AIが保存されたものを読むときの手順:
  1. `requests.yaml` の `status: requested` の項目について、`save_as`（動画は `youtube/<動画ID>/`）にファイルがあるか確かめる。
  2. あれば `look_for` を手がかりに読む。動画の映像は、ffmpeg で数秒おきの静止画に切り出して見る。
  3. わかったことを `カメラワーク.md`・`camera_moves.yaml`・`撮影ツール.md` に反映し、確度を上げる。`sources.yaml` の `read` も直す（字幕まで読んだら、そう書く）。
  4. `requests.yaml` の `status` を `used` にし、`build.py` でページを作り直す。

## 確度の付け方（撮影の知見での読み替え）

意味は `CLAUDE.md` のとおり。撮影の分野では次のように当てはめた。

| 確度 | この分野で当てはまるもの |
|---|---|
| 【実測】 | 自分たちがMC内で撮って確かめた（まだ0件） |
| 【一次】 | modの作者が書いた公式ドキュメント・配布ページ・変更履歴を読んで確認した。**機能があること**まで。操作方法や画の出来は含まない |
| 【二次】 | Minecraft Wiki、YouTubeの動画ページ（題名・概要欄・チャプター）、Web検索の要約 |
| 【未確認】 | 幾何学や仕組みからの推論、一般的な映像の用語、記憶 |

## この調査の範囲と限界（2026-11-19）

- 調べ方: Web検索でYouTubeの動画を探し、動画ページとmodの公式資料を読んだ。
- **YouTubeは、動画ページの題名・投稿者・概要欄・チャプターまで。** 字幕（発話内容）はYouTube側のbot判定で取得できず、映像も見ていない。ページ自体も低速でしか取得できなかったため、75本のうち概要欄まで読めたのは14本で、残りは題名・投稿者の確認だけ（`sources.yaml` の `read` に区別を書いた）。
- 読んでいないもの: modのソースコード、Mojangのバグ票、Flashbackの公式Discord、シェーダーの資料。
- したがって、動画の中で語られているコツ（「こう動かすときれいに見える」の類）は、ほとんど取り込めていない。人が動画を見て気づいたことは、この知見に足す価値が高い。
