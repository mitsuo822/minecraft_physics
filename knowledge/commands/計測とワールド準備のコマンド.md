# 計測とワールド準備のコマンド

> 対象: 計測用サーバを RCON で操作するための設定（server.properties・権限レベル）と、計測とワールド準備に使うコマンド（/data get entity、/summon と NBT、/gamerule、/forceload、/tick step、/time query）の書式・出力・バージョンによる違い。物理に効くエンティティのタグ（NoAI・NoGravity・Invulnerable など）も扱う。
> 使う場面: P0 環境決め（mc/server の設定）、② 実験設計（experiment.yaml の world / setup / entities を書くとき）、③ 計測（lab/runner.py・lab/parse.py を直すとき）。
> 調査日: 2026-11-20 ／ mc_version: Java Edition 26.3（2026-09-15 リリース。基盤の候補）を基準に、1.17〜26.4 スナップショット（26.4 Snapshot 10、2026-11-17）の変化を併記。統合版は扱わない。wiki の記述は 2026-11-20 取得時点の現行版（26.3 前後）のもの。
> 関連: [時間とtick](../mechanics/時間とtick.md), [時間制御とスロー](../filming/時間制御とスロー.md), [世界の形と大きさ](../mechanics/世界の形と大きさ.md), [重力と空気抵抗](../mechanics/重力と空気抵抗.md), [爆発](../mechanics/爆発.md), [Carpet](../mods/Carpet.md), [バージョン対応表](../mods/バージョン対応表.md), [E001 の experiment.yaml](../../experiments/E001_free_fall/experiment.yaml), [lab/parse.py](../../lab/parse.py), [server.properties.example](../../mc/server/server.properties.example)

## 要点

- **26.3 では `/time query gametime` の応答が「The game time is %s tick(s)」になっている。** lab/parse.py の `parse_gametime` は数値が文の末尾にある形（`The time is 12345`）しか読めず、この形では ParseError になる（2026-11-20 に関数をローカルで実行して確認）。基盤を 26.3 にするなら直す必要がある。（26.3）【一次】[S23][S24]
- `/tick` は権限レベル3が要り、公式の説明では既定ではコマンドブロックとデータパックからは使えない。サーバのコンソールは権限レベル4で実行される。関数の上限は、専用サーバでは server.properties の `function-permission-level`（既定2）で変えられると wiki の一部は書いているが、別の wiki のページは2までに制限されると書いていて食い違う（§2）。RCON から送ったコマンドの権限レベルを書いた資料は見つからなかった。（1.20.3〜26.3）【一次】[S6]【二次】[S3][S4][S5][S28]
- RCON は `enable-rcon=true` と空でない `rcon.password` で有効になる（パスワードが空だと起動しない）。暗号化されないので、wiki は localhost からの接続を勧めている。既定のポートは 25575。（26.3）【二次】[S1][S2]
- `pause-when-empty-seconds` は 1.21.2（24w33a）で追加され、既定は60秒。公式の説明では、正の値のときだけ一時停止する。wiki は、負の値なら停止しないと書いていて、0 のときの動きは書いていない。（1.21.2〜26.3）【一次】[S22]【二次】[S1]
- **NoAI を付けたモブは落ちなくなる。** wiki では、NoAI のモブは動かず、通常なら落ちる場面でも落ちない。E001 の懸念は wiki の記述で裏付けられた（【実測】ではない）。（26.3 時点の wiki）【二次】[S11]
- **Invulnerable を付けると、爆発や攻撃で動かされなくなる。** 爆風で飛ばす実験（T07・T15）に効く。wiki の説明には、重力や落下への影響は書かれていない。（26.3 時点の wiki）【二次】[S10]
- `Motion` の単位はブロック（メートル）毎 tick で、NBT で書けるのは -10.0〜10.0 まで。範囲外の値は0に戻される。（26.3 時点の wiki）【二次】[S10]
- アイテムの書式は 1.20.5（24w09a）で変わった。`Count`（byte）が `count`（int）になり、`tag` がデータコンポーネントに置き換わった。E001 の `Item:{id:"minecraft:iron_ingot",count:1}` は 1.20.5 以降の書式に合っている。（1.20.5〜）【二次】[S14]
- 1.21.9（25w31a）から、難易度ピースフルでは /summon で敵対モブを出せない。mc/server の例は `difficulty=peaceful` なので、クリーパーやゾンビを使う回（爆発など）ではこのままでは召喚できない。（1.21.9〜26.3）【一次】[S23]【二次】[S13]
- ゲームルールは 1.21.11（25w44a）でレジストリに移り、名前が camelCase から snake case に変わった（`doDaylightCycle` → `advance_time` など）。旧名がまだ通るかは、公式の説明にも wiki にも書かれていない。（1.21.11〜）【一次】[S18]【二次】[S17]
- `/forceload` で読み込んだチャンクには、プレイヤーによるチケットと同じ読み込みレベル31のチケットが付く。ただし 1.17 からチャンクの読み込みが非同期になり、コマンドを送った同じ tick に読み込まれているとは限らない。（1.17〜）【二次】[S20]
- `/tick freeze` で止めている間は、ゲーム時刻（gametime）は進まない。`/tick step` は止まっているときだけ使え、指定した tick 数だけ動かしてまた止める。（26.3 時点の wiki）【一次】[S6]【二次】[S5][S7]
- 26.3 の既定では `white-list=true` になった。許可リストが有効だと、リストにないユーザーは接続できない。オペレーターは自動で許可される、と wiki は書いている。（26.3）【二次】[S1]

## 詳細

### 1. RCON の設定（server.properties）

RCON（Remote console）は、Source RCON プロトコルを Minecraft 用に実装した、TCP/IP 上でコマンドを遠隔実行するプロトコル。Java Edition Beta 1.9 Prerelease 4 で入った。【二次】[S2]
> 「It is dangerous to expose RCON ports to the internet.」[S2]
（訳）RCON のポートをインターネットに公開するのは危険。

server.properties の項目（既定値は 26.3 が生成するファイルのもの。wiki、2026-11-20 取得）。【二次】[S1]

| 項目 | 26.3 の既定値 | このリポジトリの例 | 意味 | 確度・出典 |
|---|---|---|---|---|
| `enable-rcon` | false | true | RCON を有効にする | 【二次】[S1] |
| `rcon.password` | 空 | 自分で決める | 空のまま有効にすると、安全のため RCON が起動しない | 【二次】[S1] |
| `rcon.port` | 25575 | 25575 | RCON が待ち受ける TCP ポート | 【二次】[S1][S2] |
| `broadcast-rcon-to-ops` | true | false | RCON のコマンドの出力を、オンラインのオペレーター全員に送る | 【二次】[S1] |
| `pause-when-empty-seconds` | 60 | 0 | 誰もいなくなってから一時停止するまでの秒数（§12） | 【一次】[S22]【二次】[S1] |
| `function-permission-level` | 2 | ― | 関数の既定の権限レベル | 【二次】[S1] |
| `op-permission-level` | 4 | ― | `/op` したオペレーターの既定の権限レベル | 【二次】[S1] |
| `difficulty` | easy | peaceful | 難易度（ピースフルでの召喚の制限は §5） | 【二次】[S1] |

- server.properties は起動のたびに書き直され、ない項目や不正な値の項目は既定値になる。ファイルを書き換えたら、サーバの再起動が要る。【二次】[S1]
  > 「After changes are made to the file, the server must be restarted for them to take effect.」[S1]
- `enable-rcon` の説明は次のとおり。暗号化されず、パスワードを含む通信が傍受されうるので、localhost からの接続が望ましい。【二次】[S1]
  > 「Whether to enable rcon, which allows access to the server console over a network.」[S1]
  > 「Ideally, only connect to rcon from localhost.」[S1]
- パケットの整数はリトルエンディアン。種類（Type）は 3 がログイン、2 がコマンドの実行、0 が（複数のパケットに分かれうる）コマンドの応答。ログインが成功したときに返るパケットの種類は 3 ではなく 2。【二次】[S2]
- 応答は複数のパケットに分かれることがあり、1パケットは最大4096バイト。最後のパケットを確実に見分ける簡単な方法はない、と wiki は書いている。【二次】[S2]
  > 「The output of the command may be split over multiple packets, each containing 4096 bytes (less for the last packet).」[S2]
  > 「many commands return nothing, and there's no way of detecting unknown commands.」[S2]
  （訳）多くのコマンドは何も返さず、存在しないコマンドを検出する方法もない。

### 2. 権限レベル（/tick はデータパックから使えない）

| コマンド | 必要な権限レベル（JE） | 確度・出典 |
|---|---|---|
| `/data` | 2 | 【二次】[S8] |
| `/summon` | 2 | 【二次】[S13] |
| `/forceload` | 2（1.14.4 から） | 【二次】[S20] |
| `/tick` | 3 | 【二次】[S5] |

- JE の権限レベルは、3 がマルチプレイの管理のコマンド、4 がサーバの管理を含むすべてのコマンドを使えるレベル。【二次】[S4]
  > 「All commands are available, including commands related to server management.」[S4]
- サーバのコンソールから入れたコマンドは、権限レベル4・実行者名 `Server`・ディメンションはオーバーワールド・実行位置はワールドのスポーン地点のブロックの北西下の角で実行される。【二次】[S3]
  > 「The context of commands entered in the server console is:」[S3]
- RCON は、server.properties の説明では、ネットワーク越しにサーバのコンソールに入るためのもの（§1 の引用）。ただし、RCON から送ったコマンドの実行の文脈（権限レベル・実行位置）を明記した資料は今回見つからなかった（要確認）。【二次】[S1]
- 関数の権限レベルについて、wiki のページどうしで書き方が食い違う。【二次】[S3][S4][S28][S1]
  - 『Command context』は、JE の関数の中のコマンドは権限レベル2までに制限されると書いている。
    > 「the Execution Permission Level of commands in a function is limited to 2 or below」[S3]
  - 『Function (Java Edition)』は、シングルプレイと LAN では2まで、標準のマルチプレイのソフトウェア（専用サーバ）では `function-permission-level` の値までのコマンドを実行できると書いている。『Permission level』も、関数を解析するときの権限レベルは既定2で、server.properties で変えられると書いている。
    > 「On the default multiplayer software, a function can run any command that is no more restrictive than the permission level prescribed in」[S28]
    > 「the permission level defaults to 2 (but it can be changed in」[S4]
  - server.properties の `function-permission-level` は 1〜4 の整数で、既定は2（§1 の表）。
  - `function-permission-level` を3以上にした専用サーバで、関数から `/tick` が通るかは確かめていない（要確認）。
- /tick を追加した 23w43a の公式の説明でも、/tick は管理者以上の権限が要るので、既定ではコマンドブロックとデータパックでは使えない、とされている。wiki も、コマンドブロックからは実行できないと書いている。（1.20.3〜）【一次】[S6]【二次】[S5]
  > 「The command requires elevated permissions (admins and above) and so it is not by default available in command blocks and datapacks.」[S6]
  > 「The /tick command cannot be executed from a command block.」[S5]

### 3. /data get entity の出力

- `/data get entity <対象> [<パス>] [<倍率>]` は、エンティティの NBT 全体か一部を、色付きで実行者に表示する。【二次】[S8]
  > 「Read off the entire NBT data or the subsection of the NBT data from the targeted block position or entity to the executor with syntax highlighting」[S8]
- 26.3 の英語の言語ファイルでの応答の文（lab/parse.py が前提にしている文と同じ）。【一次】[S23]

| 場面 | 26.3 の文（en_us） | parse.py の扱い |
|---|---|---|
| パスを指定して読む | 「%s has the following entity data: %s」[S23] | `entity data:` の後ろを読む |
| 倍率つきで読む | 「%s on %s after scale factor of %s is %s」[S23] | 未対応 |
| 対象のエンティティがいない | 「No entity was found」[S23] | `is_no_entity` で検出 |
| パスのタグがない | 「Found no elements matching %s」[S23] | `is_no_entity` で検出（エンティティがいないのと区別していない） |

- 倍率を付けると、値に倍率を掛けてから切り捨てた整数がコマンドの結果（`/execute store result` で保存できる値）になる。【二次】[S8]
  > 「then rounded down」[S8]
- 倍率なしで数値のタグを読んだときの結果の値も、切り捨てた整数。リストを読むと要素の数、文字列を読むと長さが結果になる。【二次】[S8]
- 26.3（snap10）で、`/data modify` に新しい値の取り出し元 `compute` が加わった。【二次】[S8]
- `Pos` は X・Y・Z の3つの double、`Motion` は dX・dY・dZ の3つの double で、単位はメートル毎 tick。`OnGround` は真偽値で、地面に触れていれば true。【二次】[S10]
  > 「doubles describing the current X, Y, and Z position」[S10]
  > 「velocity of the entity in meters per game tick. Only allows between 10.0 and -10.0 (inclusive), else resets to 0.」[S10]
  > 「if true, the entity is touching the ground.」[S10]
- 落下の距離は `fall_distance`（double）に入っていて、大きいほど着地のダメージが大きい。【二次】[S10]

### 4. NBT（SNBT）の数値の書き方と精度

- `/data get` などで取り出した NBT は SNBT（文字の形）に変換される。変換後の数値には、int 以外は型の文字が付く（byte は b、short は s、float は f、double は d、long は L）。NBT には真偽値の型がなく、byte の 0 と 1 で表す。`OnGround` は真偽値のタグ（[S10]）なので、この2つの記述どおりなら `1b`・`0b` で出るはずだが、実機の表示は確かめていない（要確認）。【二次】[S9][S10]
  > 「After converted, a number is always followed by a letter (lowercase for b, s, f, d, and uppercase for L) except」[S9]
- NBT の double は64ビットの倍精度浮動小数点数。【二次】[S9]
- ただし、`/data get` の表示で double が**何桁まで**出るか、指数表記になる場合があるかは、今回読んだ資料に書かれていなかった（要確認。lab/parse.py の正規表現は指数表記も読める形になっている）。
- 1.21.5 で SNBT が広がった。25w04a で型の混ざったリストを書けるようになり、25w09a で `.1`・`2e3`・`123_456` のような数の書き方、16進・2進、符号の接尾辞が使えるようになり、空のキーを含むパスは使えなくなった。25w10a で `bool(...)`・`uuid(...)` が加わった。（1.21.5〜）【二次】[S9]
  > 「SNBT (textual representation of NBT-like data) has been expanded to accept heterogenous lists」[S9]

### 5. /summon と NBT・アイテムの書式（1.20.5 以降の変化）

- 書式は `summon <エンティティ> [<位置>] [<NBT>]`。位置を省くとコマンドの実行位置に出る。サーバのコンソールから送ると、実行位置はワールドのスポーン地点のブロックの北西下の角になる（§2）。RCON から送ったときの実行位置は資料に書かれていない（要確認）。【二次】[S13][S3]
  > 「Specifies the position to summon the entity. If not specified, defaults to the position of the command's execution.」[S13]
- 1.21.9（25w31a）から、難易度がピースフルのとき敵対モブ（monster）の召喚は失敗する。26.3 の言語ファイルにも、そのときの文がある。（1.21.9〜26.3）【二次】[S13]【一次】[S23]
  > 「The command now fails when trying to summon monsters while the difficulty is set to Peaceful.」[S13]
  > 「Monsters cannot be summoned in Peaceful difficulty」[S23]
  - 注意: 同じ wiki ページの「Result」の表は、この場合の結果を古いままにしているように読める。履歴の行と言語ファイルのほうを信じる（実機でも確かめる）。【二次】[S13]
- 成功したときの文は「Summoned new %s」、位置が不正なときは「Invalid position for summon」。【一次】[S23]

**アイテムの書式（1.20.5、24w09a で変更）** 【二次】[S14]

| | 1.20.4 まで | 1.20.5 以降 |

| 追加の情報 | `tag` | `components`（データコンポーネント） |
| 例（wiki の /summon のページ） | ― | `summon item ~ ~ ~ {Item:{id:"minecraft:diamond_pickaxe",count:1,components:{"minecraft:unbreakable":{}}}}` |

### 6. 物理に効くエンティティのタグ

| タグ | wiki の説明（26.3 時点） | 物理への影響 | 確度・出典 |
|---|---|---|---|

| `NoGravity` | 自然には落ちない。false のときはタグ自体がない | 重力による落下を止める（落下以外への影響は wiki に書かれていない） | 【二次】[S10] |

| `Silent` | 音を出さない | 撮影で鳴き声を消せる（物理には関係しない） | 【二次】[S10] |
| `Tags` | スコアボードのタグのリスト | runner は `mcphys`・`track_<id>` で追跡に使っている | 【二次】[S10] |

> 「Setting to true disables the mob's AI. The mob does not and cannot move, to the extent of not falling when normally able.」[S11]
（訳）true にするとモブの AI が止まる。モブは動かず、動けない。通常なら落ちる状況でも落ちない。
> 「if true, the entity does not fall down naturally. Does not exist if set to false.」[S10]
> 「cannot be moved by fishing rods, attacks, explosions, or projectiles」[S10]
> 「if true, this entity is silenced.」[S10]

### 7. 落下ブロックとアイテムのエンティティ（E001 で使うもの）

- 落下ブロック（`falling_block`）の `Time` は存在した tick 数。600 を超えると消える。Y=-64 にいるか建築できる高さの外にいる場合は、100 を超えると消える。【二次】[S16]
  > 「or above 100 while the block is at Y=-64 or is outside building height, the entity is deleted.」[S16]
- `HurtEntities`（下にいるエンティティにダメージを与えるか）は、金床と鍾乳石では既定で1だが、召喚した落下ブロックでは既定で0。【二次】[S16]
  > 「and to 0 for the other vanilla falling blocks and any summoned falling block.」[S16]
- 1.9（15w38a）から、落下ブロックがブロックに戻るのは、着地した面の高さの小数部分がごく小さい（0.009999999776482582 未満）ときだけになった。【二次】[S16]
- アイテムのエンティティ: `PickupDelay` を 32767 にすると減らなくなり、拾えなくなる。`Age` を -32768 にすると増えなくなり、自然には消えない（通常は 6000 tick で消える）。【二次】[S15]
  > 「If set to 32767, the PickupDelay does not decrease, preventing the item from being picked up.」[S15]
  > 「If set to -32768, the Age does not increase, preventing the item from despawning automatically.」[S15]
- 同じ種類のアイテムは、0.5×0.25×0.5 の範囲に入ると1つにまとまることがある。まとまる処理は普通は40 tick ごと（ブロックの境目をまたぐ動きでは2 tick ごと）。【二次】[S15]

### 8. ゲームルール名の新旧（1.21.11 で改名）

### 9. /forceload

- 書式は `forceload add <from> [<to>]`・`forceload remove ...`・`forceload query [<pos>]`。座標はチャンク番号ではなくブロックの座標で指定する。1回に指定できるのは256チャンクまで。【二次】[S20]
  > 「More than 256 chunks are specified.」[S20]
- 強制的に読み込んだチャンクには、プレイヤーによるものと同じ読み込みレベル31のチケットが付き、ゲームのすべての処理が行われる。【二次】[S20]
  > 「Forced chunks get load ticket with load level of 31, the same level as the ticket caused by a player」[S20]
- ただし、モブのスポーン・落雷・火の広がりは行われない（wiki の文はまだ旧ゲームルール名の `allowFireTicksAwayFromPlayer` を挙げている。今は §8 の `fire_spread_radius_around_player`）。1.21.5（25w06a）から、強制読み込みのチャンクでもランダムティックが起きる。【二次】[S20]
  > 「process all updates except for mob spawning, lightning strikes, and fire spreading」[S20]
- **1.17（20w45a）からチャンクの読み込みが非同期になり、/forceload で選んだチャンクが、コマンドを実行した同じ tick に読み込まれているとは限らない。** 【二次】[S20]
  > 「are no longer guaranteed to be loaded on the same tick that the command is run.」[S20]
- 比較として、server.properties の `simulation-distance` は、プレイヤーからどれだけ離れた生き物まで更新するかの距離で、その外のエンティティは更新されない。【二次】[S1]
  > 「If entities are outside of this radius, then they are not ticked by the server and they are not visible to players.」[S1]

### 10. スーパーフラットの生成設定とシード

- サーバでスーパーフラットにするには `level-type=minecraft\:flat`。層・バイオーム・構造物は `generator-settings` に JSON で書く。wiki の例（Classic Flat を再現する設定）。【二次】[S21][S1]
  ```properties
  generator-settings={"biome":"minecraft:plains","layers":[{"block":"minecraft:bedrock","height":1},{"block":"minecraft:dirt","height":2},{"block":"minecraft:grass_block","height":1}]}
  level-type=minecraft\:flat
  ```
- 既定のスーパーフラットの地表は Y=-60（層とその高さの詳細は [世界の形と大きさ](../mechanics/世界の形と大きさ.md)）。E001 の `origin: [0, -60, 0]` のコメントの値と合う。【二次】[S21]
  > 「the surface of the world is completely flat and at Y=-60」[S21]
- JE の既定のスーパーフラットでは村がよく生成され、要塞も生成されうる。モブは普通にスポーンし、高さが低いのでスライムがよく出る。【二次】[S21]
- `generate-structures=false` で村などの構造物を止められるが、ダンジョンは生成される。【二次】[S1]
  > 「Dungeons still generate if this is set to false.」[S1]
- `level-seed` を空にするとランダムなシードになる。【二次】[S1]
  > 「A random seed is used if left blank.」[S1]
- 1.3.1（12w18a）以降、ワールドを作ったあとは level.dat の値が server.properties より優先される。`level-type`・`generator-settings`・`level-seed` を変えたら、ワールドを作り直す必要がある（mc/server/README.md の手順と同じ）。【二次】[S21]
  > 「any data in the level.dat file overrides the values in server.properties」[S21]

### 11. /tick step を RCON から送るとき（非同期性）と /time query gametime

- `/tick freeze` は、プレイヤーとプレイヤーが乗っているエンティティを除いて、ゲームの要素を止める。撮影用のクライアントのプレイヤーは止まらない。【二次】[S5]
  > 「Freezes ticking. All gameplay elements are not ticked, except players and any entity a player is riding.」[S5]
- `/tick step [<time>]` は止まっているときだけ使え、指定した時間だけ動かして、また止める。時間を省くと1 tick。単位は t（tick、既定）・s（20 tick）・d（24000 tick）。（1.20.3〜。時間の省略は 23w44a から）【一次】[S6]【二次】[S5]
  > 「Unfreezes ticking, runs specified amount of time, and refreezes. Only works if ticking is frozen.」[S5]
  > 「It runs the game for the specified number of ticks and then freezes the game again.」[S6]
- 26.3 の言語ファイルでは、成功したときの応答は「Stepping %s tick(s)」、止まっていないときは「Unable to step the game - the game must be frozen first」。【一次】[S23]
- 26.3（snap1）から、`/tick step`・`/tick step stop`・`/tick sprint stop` は、失敗したときに文を出して0を返すだけでなく、エラーを出すようになった。【二次】[S5]
  > 「The following subcommands will now signal an error instead of just printing an error message and returning 0」[S5]
- **応答が返った時点で1 tick が進み終わっているか**は、今回読んだ資料には書かれていない。docs/MC実行基盤.md と lab/runner.py は、tick step が非同期に進むものとして、`time query gametime` が1増えるまで待ってから読む作りになっている。これはリポジトリ内の判断で、まだ実機で確かめていない【未確認】。
- /tick で止めている間は、gametime・昼夜の時間・時刻・日数は進まない。gametime は64ビットの整数で保存されるが、コマンドが返す値は 2^31-1 で割った余り。【二次】[S7]
  > 「the four times above do not elapse.」[S7]
  > 「Stored as a 64-bit signed integer, but returned modulo」[S7]
- 26.1（snap3）で /time はワールド時計（world clock）を元にする作りに変わった。26.3 の書式には `time query gametime`・`time query time`・`time set (<time>|day|night|noon|midnight)`・`time pause` などがある。【二次】[S7]
- **26.3 の言語ファイルでは `time query gametime` の応答は「The game time is %s tick(s)」**（26.4 Snapshot 10 でも同じ）。時計の時刻は「Clock %s is at %s tick(s)」、旧来の「The time is %s」の文も残っている。【一次】[S23][S24][S25][S26]
  - lab/parse.py の `parse_gametime` は、数値が末尾にある文しか読まない。`The game time is 12345 tick(s)` を渡すと ParseError になった（2026-11-20、リポジトリのコードをローカルで実行して確認。MC の実機での確認ではない）。テスト（tests/test_pipeline.py）と模擬サーバ（lab/sim/fake_server.py）も旧来の文を前提にしている。【一次】[S23]
  - この文がどの版から使われているか（1.21.x では旧来の文か）は、今回確かめていない（要確認）。

### 12. pause-when-empty-seconds と、その他のサーバ設定

- `pause-when-empty-seconds` は 1.21.2（24w33a）で追加された。【一次】[S22]
  > 「New server.properties option: pause-when-empty-seconds (default 60)」[S22]
  > 「When set to a positive value, causes the server to pause when no player has been online for that many seconds」[S22]
  （訳）正の値にすると、プレイヤーが誰もいない状態がその秒数続いたときにサーバが一時停止する。
- wiki（26.3 時点）の説明は次のとおりで、0 のときの動きは書かれていない。【二次】[S1]
  > 「How many seconds have to pass after no player has been online before the server is paused.」[S1]
  > 「If set to a negative value, the server is never paused.」[S1]
- 26.3（snap2）で、`white-list` の既定値が true になった。許可リストが有効だと、リストにないユーザーは接続できない。オペレーターは自動で許可される。【二次】[S1]
  > 「Ops are automatically whitelisted, and there is no need to add them to the whitelist.」[S1]
- Minecraft Server Management Protocol（1.21.9、25w35a で追加）は、専用サーバを JSON-RPC 2.0 over WebSocket で管理する API。既定では無効で、40文字の秘密の文字列で認証する。【二次】[S27]
  > 「is a server management API (JSON-RPC over WebSocket) for dedicated servers.」[S27]
  > 「Core method groups: players, allowlist, operators, server (save, stop), server settings, game rules.」[S27]
  - 任意のコマンドを実行する口は、wiki の一覧には見当たらない。`pause_when_empty_seconds` を読み書きする口はある。【二次】[S27]

## このチャンネルでの使い方（提案）

> ※この節は上の事実から導いた提案で、事実ではない。

- **基盤を 26.3 にするなら、P1 の前に lab/parse.py の `parse_gametime` を直す。** `The game time is N tick(s)` と旧来の `The time is N` の両方を読めるようにし、tests と lab/sim/fake_server.py の応答も 26.3 の文に合わせる。実機の最初の応答は控えておく。（根拠: [S23][S24]、§11）
- mc/server/server.properties.example の `pause-when-empty-seconds=0` を `-1` にする。公式（正の値で停止）と wiki（負の値なら停止しない）の両方の説明で「停止しない」になる値だから。（根拠: [S22][S1]）
- `broadcast-rcon-to-ops=false` は残す。撮影用のクライアントでオペレーターとして入ると、毎 tick の `data get` の出力がチャットに流れるのを防げる。（根拠: [S1]）
- 26.3 の新しいサーバでは、撮影用のアカウントをオペレーターにするか、`/whitelist add` で許可リストに入れる（ローカルだけで使うなら `white-list=false` でもよい）。（根拠: [S1]）
- /tick は既定ではデータパックから使えないので、止める・1 tick 進める・読む、の流れは RCON（lab/runner.py）で行う方式を続ける。データパックにするのは /tick を使わない部分（演出など）だけにする。`function-permission-level` を上げる方法は、wiki の記述が食い違うので頼らない。（根拠: [S3][S4][S5][S6][S28]）
- RCON から `/tick` が通るかは、P0 で `tick query` を1回送って確かめる。召喚では位置を必ず書く（RCON の実行位置がわからないため）。（根拠: §2・§5）
- experiment.yaml の entities では、落下の実験に `NoAI` を使わない。動かないようにしたいなら `NoGravity` の有無で区別する。E001 の、NoAI を付けると重力も止まるかもしれないという注意は【二次】で裏付けられたので、E001 の実行で【実測】にする。（根拠: [S11][S10]）
- 爆発の実験（T07・T15）では、モブに `Invulnerable` を付けない。ダメージで死なないようにする別の方法は [爆発](../mechanics/爆発.md) で検討する。`Motion` を NBT で与えるときは ±10 の範囲に収める。（根拠: [S10]）
- クリーパーなど敵対モブを召喚する回は、難易度をピースフル以外にして、自然スポーンは `spawn_mobs false`（必要なら `spawn_monsters false`）で止める。（根拠: [S13][S23][S17]）
- runner の準備で `forceload add` を送ったら、すぐに召喚せず、`forceload query` か召喚の応答（「Summoned new ...」）を見て、チャンクが読み込まれたことを確かめてから始める。（根拠: [S20][S23]）
- E001 のアイテムの NBT（`count:1`、`PickupDelay:32767`）は 1.20.5 以降の書式で正しい。experiment.yaml の注意（count の小文字など）の【未確認】は【二次】に上げてよい。間隔（4ブロック）は、アイテムがまとまる範囲より十分広い。（根拠: [S14][S15]）
- 600 tick を超える落下（終端速度の実験で高いところから落とす場合）では、落下ブロックが途中で消える。落下ブロックではなくモブやアイテムを使うか、`Time` の扱いを実機で確かめる。（根拠: [S16]）
- ゲームルールは新しい名前（`advance_time` など）で書く（E001 は既にそうなっている）。P0 で 26.3 のサーバに旧名を1つ打ち、通るかどうかを記録する。（根拠: [S18][S17]）
- 火を使う実験では、プレイヤーがいないと火が広がらない場合があるので、`fire_spread_radius_around_player` を確かめてから使う。（根拠: [S18][S20]）
