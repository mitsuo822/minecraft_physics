# 世界の形と大きさ（高さの範囲・ワールドボーダー・ファーランド・太陽と月・スーパーフラット）

> 対象: ワールドの縦の範囲（建築の上限・下限、奈落）、横の端（ワールドボーダー、3,000万ブロックの境界、ファーランド）、太陽・月の動き（場所で変わるか）、スーパーフラットの既定の層と高さ。
> 使う場面: テーマ T13（エラトステネスの方法でMCの世界の大きさを測る）の企画・台本、撮影用ワールドの作成、座標や高さを台本で言うとき。
> 調査日: 2026-11-19 ／ mc_version: 主に Java Edition。2026-11-19 時点の minecraft.wiki の記載（最新の正式版は Java Edition 26.3、2026-09-15 リリース [S4]）。統合版（Bedrock）の違いは明記する。
> 関連: [流体.md](流体.md), [爆発.md](爆発.md), [時間とtick.md](時間とtick.md)（1日 24000 tick）, [光.md](光.md)（空の光）, [../filming/シェーダーと画質mod.md](../filming/シェーダーと画質mod.md)（影の出るシェーダー）, [../filming/時間制御とスロー.md](../filming/時間制御とスロー.md)

## 要点
- Java 版のオーバーワールドで置ける高さは Y=-64 から（上面で）Y=320 まで。ネザーとエンドは Y=0〜256。1.18 で上下に 64 ブロックずつ広がり、384 層になった。【二次】[S1][S5]
- 高さの上限・下限はブロックだけの制限で、エンティティはその外へも行ける。Java 版のテレポートの上限は Y=20,000,000。オーバーワールドでは Y=-128 より下で奈落のダメージを受ける。【二次】[S1][S5]
- データパックの次元の設定で、高さの範囲は最大 Y=-2032〜2031 まで変えられる（16 の倍数）。【二次】[S1]
- ワールドボーダーは既定で原点から X/Z ±29,999,984（直径 59,999,968）。その1チャンク外の ±30,000,000 に見えない『壁』があり、トロッコで ±30,000,208、ボートで ±30,000,544 まで行けるのが絶対的な端。【二次】[S1][S2]
- ワールドボーダーは Java 版だけの仕組み。統合版には固い横の端がなく、コマンドの制限が ±30,000,000 にある。【二次】[S1][S2]
- ファーランドは、地形のノイズが整数のオーバーフローで壊れて出る巨大な壁の地形。Java では約 12,550,824 で起き、Beta 1.8 で直った。【二次】[S3]
- Java 26.3 Pre-Release 1 でデバッグ用の設定 `ENABLE_FARLANDS` が入り、ファーランドを再び出せるようになった（ネザーとエンドだけ）。目的は直す処理（modulo の修正）の性能を比べるため、と wiki は書き、その出典に gegybeans のツイート（2026-09-03）を挙げている。【二次】[S3][S4]
- 太陽と月はプレイヤーのまわりを回るように見え、昼に真上、夜中に月が真上に来る。空の角度の式は**時刻だけで決まり、場所が入っていない**。【二次】[S7]
- 太陽と月は東から昇り西に沈む（Java では Beta 1.9 Prerelease 4 から。それまでは北から昇っていた）。【二次】[S7][S8]
- 1日は 24000 tick（20分）で、現実の72倍の速さ。昼は10分、日没50秒、夜8分20秒。月は8つの相を持つ。【二次】[S7]
- 既定のスーパーフラットは、岩盤1層・土2層・草ブロック1層、バイオームは平原。地表は Y=-60（今の wiki の記述。最下層が Y=-64 になったのは 1.18 の 21w37a から）。【二次】[S6]
- 海面は 62 層（ブロックの下面で数えた場合。上面で数えると 63）。Beta 1.8 で 63 から 62 に変わった。【二次】[S5]

## 詳細

### 縦の範囲（建築の上限・下限）
- 建築の上限・下限は、データパックの `dimension_type` の `min_y`（-2032〜2031、16 の倍数）と `height`（16〜4064、16 の倍数）で決まる。どう設定しても下限は Y=-2032 より下にならず、上限は Y=2031 を超えない。【二次】[S1]
> 「the minimum build height cannot be below Y=-2032, and the maximum build height cannot exceed Y=2031」[S1]
- 標準のデータパックの値。【二次】[S1]
> 「The minimum build heights in the vanilla data pack are Y=-64 in the Overworld and Y=0 in the Nether and End.」[S1]
> 「values) in the vanilla data pack are Y=320 in the Overworld and Y=256 in the Nether and the End.」[S1]
- 上の Y=320 は『置ける最も高いブロックの上面』の値（Altitude の記事の表）。【二次】[S5]
- エンティティにはこの制限がない。【二次】[S1]
> 「which are allowed to travel to and exist above the maximum and below the minimum build heights」[S1]
- 建築の下限から 64 ブロック以上下にいる生物（エンダードラゴン以外）は、奈落のダメージを受ける。オーバーワールドでは Y=-128 より下。【二次】[S1][S5]
> 「Players below this height in Overworld take void damage in」[S5]
- 統合版: オーバーワールドの下は Y=-62 より下の岩盤の床で止まる。ネザーは Y=1 の床と Y=128 の天井。ブロックを置ける範囲はオーバーワールドで Y=-64/320、ネザーとエンドで Y=0/128。【二次】[S1]

- 1.13（17w50a）より前は Y ±30,000,000 を超えるとゲームが落ち、17w50a からはキックされるようになった。1.17（21w13a）から、その高さでもキックされない。1.16（20w06a）から Y ±20,000,000 を超えるテレポートはできない。【二次】[S1]

### 横の端（Java 版）
端は何層にもなっている。【二次】[S1]

| 位置（X/Z） | 何があるか | 出典・確度 |
|---|---|---|
| ±29,999,984 | ワールドボーダー（既定）。プレイヤーは越えられない | [S1][S2]【二次】 |
| ±29,999,999.5 | コマンドで受け付ける座標の上限（ソースに書き込まれた値） | [S1]【二次】 |
| ±30,000,000 | 見えない『壁』。越えたプレイヤーの位置をここに戻す（スペクテイターでも） | [S1]【二次】 |
| ±30,000,208 | トロッコで行ける限界（スーパーフラットでレールを敷いた場合） | [S1]【二次】 |
| ±30,000,544 | ボートで行ける限界。ここより外にはチャンクが生成されない『絶対的な端』 | [S1]【二次】 |
| ±33,554,432 | ソースを改造して端を広げた場合に、ブロックが見えなくなる限界（2^25） | [S1]【二次】 |
| ±2,147,483,647 | ソースを改造した場合の最終的な上限 | [S1]【二次】 |

> 「which lies at X/Z ±29,999,984 by default」[S1]
> 「preventing the player from advancing by setting any players' positions beyond it to it, even in spectator mode」[S1]
> 「This value is hard-coded into the game's source code.」[S1]
> 「This is considered to be the absolute edge of the Minecraft world.」[S1]
- ±30,000,000 より外では、生物が湧かず、光の更新が止まり（太陽と月の光は除く）、アイテムが少し震える。雨のパーティクルは、地形にかかわらず海面の高さで地面に当たる。【二次】[S1]
- ソースを改造して端を ±30,000,544 より外に広げると、X/Z ±2,000,000,000 でもふつうに遊べる。今のバージョンでは距離による不具合の多くが直されているため、と wiki は書く。【二次】[S1]
- 歩く速さ（走らない）は 4.3 ブロック/秒。1日6時間歩くと 92,880 ブロック/日で、ファーランド（1,250万）まで 136 日弱。境界はその3倍近く遠い。【二次】[S1]
> 「Time-wise, the walking (not sprinting) speed is 4.3 blocks per second.」[S1]
- 実際に歩いて 3,000 万のワールドボーダーまで行った人がいる（Java 1.17、Figonometry）。【二次】[S1]
> 「has been reached by Figonometry in 1.17」[S1]
- wiki の豆知識では、既定のワールドボーダーの内側のブロック数は 921,599,016,960,262,144 個（英語で 921 quadrillion、日本語の単位では約 92 京。空気を含む）。ただしこの計算は高さ Y=0〜255 を前提にしている（今の -64〜319 ではない）。【二次】[S1]
> 「there is a total of 921,599,016,960,262,144 (921 quadrillion) blocks in the default world border (Including air blocks)」[S1]
- 履歴: Infdev 20100313 で ±32,000,000 より外にブロックが生成されなくなった。Beta 1.8 で『偽のチャンク』が ±30,000,000 から始まるようになった。1.8（14w17a）でワールドボーダーが追加された。【二次】[S1]

### ワールドボーダー（Java 版だけ）
- 4つの面からなり、既定ではそれぞれ原点から 29,999,984 ブロック。直径 59,999,968 が `/worldborder` の既定値。【二次】[S2]
> 「This means a diameter of 59,999,968, which is the default value set in the」[S2]
- 色: 止まっているときは水色、広がっているときは緑、縮んでいるときは赤。Y=-2048 より下・Y=2048 より上では見た目が続かないが、境界としては働く。【二次】[S2]
- ボーダーの外にいるプレイヤー（クリエイティブとスペクテイター以外）は、ボーダーから 5 ブロックより外でダメージを受け続ける。【二次】[S2]
> 「with damage being inflicted when the player is outside an area that is 5 blocks past the world border on any side」[S2]
- エンティティはボーダーを通り抜けられない。ただしディスペンサーをボーダーの端に向けると、アイテム・投射物・TNT などを外へ撃ち出せる。【二次】[S2]
- ボーダーの外でも、TNT などの爆発はふつうに地形を壊す。流体はボーダーを越えて流れる（[流体.md](流体.md)）。落下するブロックはアイテムになり、ピストンとホッパーは動かない。【二次】[S2]
- 統合版はワールドボーダーを持たない（記事が Java 専用の印つき）。統合版にはコマンドの制限が ±30,000,000 にあり、`/tp` はそれより遠くへ行けない。ネザーゲートを使うとオーバーワールドで ±31,999,872 まで行ける。【二次】[S1][S2]
> 「Bedrock Edition technically has no hard boundary」[S1]

### ファーランド
- ファーランドは地形生成の不具合で、地形の形を決めるノイズ生成器が整数のオーバーフローで壊れたときに出る、スポンジ状の巨大な壁の地形。内部は長く暗いトンネル。【二次】[S3]
> 「The insides of the Far Lands consist of long dark tunnels, with sharp edges and extreme landscapes.」[S3]
- 壊れる距離（Java、32ビット）: low noise と high noise が 12,550,824 で壊れ、ファーランドになる。selector noise は既定でその 80 倍遠く（1,004,065,924）で壊れ、『さらに遠い地（Farther Lands）』になる。【二次】[S3]
> 「breaks down 80 times further than low and high noise by default, giving rise to what is known as the」[S3]
- Java では Beta 1.8 Pre-release、統合版では 1.17.30 で直された。Java 1.8 で、以前の境界の2倍以上遠くに意図したワールドボーダーが置かれた。【二次】[S3]
- Java 26.3 Pre-Release 1 で、デバッグ用の設定 `ENABLE_FARLANDS` が追加された。Beta 1.8 の『modulo』の修正を無効にする。いわゆるファーランドはネザーとエンドでだけ出る（オーバーワールドでは、それより手前でほかの要素が壊れるため）。【二次】[S3][S4]
> 「The traditional form of the Far Lands only appear in the Nether and the End as multiple other factors break down in the Overworld way before the Far Lands can appear there.」[S4]
> 「The purpose of this debug flag is to compare the performance of the modulo fix as it had a non-zero performance cost.」[S4]
- wiki は、26.3 ではすべてが float にキャストされるため、出てくるファーランドは正確ではなく誤解を招く、と注意書きしている。【二次】[S3]

### 太陽と月の動き（T13 の核心）
- 太陽と月はプレイヤーのまわりを回るように見え、正午に太陽が、真夜中に月が真上に来る。太陽と月は星に対していつも同じ位置で、互いの位置も変わらない。そのため日食は起きない。【二次】[S7]
> 「appear to rotate around the player, appearing directly overhead at midday and midnight, respectively」[S7]
> 「Solar eclipses are therefore impossible」[S7]
- 空の角度の式（正午を 0°、t は夜明けからの tick 数）は α = (1 − cos(π × mod₁((t − 6000)/24000)) + mod₄((t − 6000)/6000)) × 60°。**入力は時刻 t だけ**で、プレイヤーの位置は入っていない。【二次】[S7]
- 空（太陽・月・星）は、正午と真夜中に速く、日の出と日の入りのころに遅く動く。【二次】[S7]
> 「The sky, including sun, moon, and stars, move faster during noon and midnight and slower during sunrises and sunsets.」[S7]
- 太陽と月は東から昇り西に沈む。日没のとき、太陽は西の地平線に沈み、月は東の地平線から昇る。【二次】[S7][S8]
- 太陽の通り道は地面に垂直な完全な円で、正午に天頂（真上）を通る。描画の処理に地軸の傾きや緯度を表す回転・ずれが入っていないため、北半球の地球のように南へ寄ることはない（Sun の記事の豆知識）。Vibrant Visuals のリソースパックでは軌道のずれを付けられる。【二次】[S8]
> 「The sun's trajectory forms a perfect vertical circle perpendicular to the ground plane, passing directly through the zenith at noon.」[S8]
> 「During sunset, the sun descends on the western horizon, and the」[S7]
- 昔は太陽が北から昇っていた。不具合で、しばらく残されていたが、Java の Beta 1.9 Prerelease 4（1.0.0 の開発版）で東から昇るようになった。統合版では 1.1.0（alpha 1.1.0.0）で同じ修正。【二次】[S7][S8]
> 「This was a bug and was fixed in Beta 1.9 Prerelease 4, so the Sun and Moon now both rise in the east」[S7]
- 時刻の流れはネザーやエンドにいるあいだも続く。時計はネザーとエンドではでたらめに回る（その次元に昼夜がないため）。【二次】[S7]
- 統合版の『Vibrant Visuals』では、太陽が全体を照らす方向のある光源として扱われ、ブロック・エンティティ・雲がピクセル状の影を落とす。【二次】[S8]
> 「the sun is considered a global directional light source, which creates pixelated shadows from blocks, entities, and clouds on all objects」[S8]
- Java 版では、太陽が夜のあいだも奈落の下に見えている。wiki はこれを Java 26.4 までの挙動として印を付けている（26.4 で変わる予定）。【二次】[S8]

### 1日の長さと時刻
- 昼夜の周期は20分。MC の時間は現実の72倍の速さ（1日 24000 tick、20 tick/秒のとき）。MC の1時間 = 1000 tick = 50秒。【二次】[S7]
> 「The daylight cycle is a 20-minute-long cycle」[S7]
- 昼（日没・日の出を除く）は 0〜12000 tick で10分。日没は 12000〜13000 tick の50秒。夜は 13000〜23000 tick の8分20秒。【二次】[S7]
> 「Sunset is the period between daytime and nighttime, and always lasts 50 seconds (1000 ticks).」[S7]
- 月は夜ごとに8つの相のどれかで見え、相によってゲーム内の出来事が変わることがある。【二次】[S7]
> 「appears in one of eight different phases each night」[S7]
- 昼夜の進行を止めるゲームルールは、Java では `advance_time`、統合版では `dodaylightcycle` と書かれている。Java の `/time set` の名前つきの値は `minecraft:day`（1000）、`minecraft:noon`（6000）などの名前空間つきの表記。【二次】[S7]
- Java の `doDaylightCycle` は 1.6.1（13w24a）で追加された、と履歴にある。今の `advance_time` に名前が変わったバージョンは、この記事からは読み取れない。【二次】[S7] Game rule の記事の履歴では、1.21.11（25w44a）ですべてのゲームルールが snake case の名前に変わり、`doDaylightCycle` は `advance_time` になった（詳細は [時間とtick.md](時間とtick.md)）。【二次】[S9]
- `/time set` で設定できる最大値は 2,147,483,647（32ビット整数の上限）。【二次】[S7]
- 細かい tick の話は [時間とtick.md](時間とtick.md)、/tick コマンドは [../filming/時間制御とスロー.md](../filming/時間制御とスロー.md)。

### スーパーフラット
- 既定のスーパーフラットは、岩盤1層・土2層・草ブロック1層で、バイオームは平原。Java では村がよくでき、要塞もある。統合版では地物や構造物は生成されない。【二次】[S6]
> 「In the default superflat world, the surface of the world is completely flat and at Y=-60, except for villages and other structures if they are enabled.」[S6]
- 層は Y=-64 から数える（岩盤 Y=-64、土 Y=-63・-62、草ブロック Y=-61、上面が Y=-60）。（[S6] の層の数と [S5] の下限からの計算）
- 高さが低いのでスライムがよく湧く。【二次】[S6]
- 履歴（Java）: 1.17 の開発版 21w06a で Y=-64 で生成されるようになり、21w15a で Y=4 に戻り、1.18（21w37a）で再び Y=-64 になった。統合版は 1.18.0 から新しい平らな世界が Y=-64 で生成され、既存の世界は Y=0 のまま。【二次】[S6]
- 『Classic Flat』のプリセットは同じ層だが、要塞ができない（村だけ）点が既定と違う。【二次】[S6]
- 層の設定の例（Classic Flat を作る `generator-settings`）。【二次】[S6]
> 「{"block":"minecraft:bedrock","height":1},{"block":"minecraft:dirt","height":2},{"block":"minecraft:grass_block","height":1}」[S6]

## このチャンネルでの使い方（提案）
> ※この節は上の事実から導いた提案で、事実ではない。
- **T13 の仮説と落ち**: 空の角度の式に場所が入っていないので、どれだけ離れた2地点でも、同じ時刻の太陽の高さは同じはず。エラトステネスの方法（2地点の影の角度の差から地球の大きさを出す）を当てはめると角度の差は 0 → 『MC の地球は無限に大きい（または平ら）』が結論になる。backlog の note どおり。（根拠: [S7]）
- 2地点は、遠いほど説得力がある。テレポートで X=0 と X=29,000,000 付近（ボーダーの内側）を比べれば、約 2,900 万ブロック（1ブロック = 1 m なら約 2,900 万 m）離れた2地点で角度が変わらないことを示せる。現実の地球の大きさと比べる場合は、地球の円周の値の出典をこの文書に持っていないので、台本に入れる前に出典を取る。（根拠: [S1][S2][S7]）
- 影で角度を測るなら、Java の標準の描画に太陽の向きの影はない可能性があるので（今回の資料では確認できず）、影の出るシェーダー（Iris）を使うか、F3 で太陽を真正面に見たときの視線の角度を測る方法を検討する（[../filming/シェーダーと画質mod.md](../filming/シェーダーと画質mod.md)）。（根拠: [S8] は統合版の Vibrant Visuals の影だけを述べている）
- 時刻は `/time set` で固定し、昼夜の進行のゲームルールを止めてから2地点を測る。チャンクを読み込むまでの時間で時刻がずれないようにする。（根拠: [S7]）
- 『世界の果て』の回（3,000万の壁、ボートで ±30,000,544）は、物理の回の箸休めやショートのネタになる。ファーランドは 26.3 のデバッグ設定で再現できるが、wiki は不正確と注意しているので、出すなら『再現版』と明記する。（根拠: [S1][S3][S4]）
- 撮影用のスーパーフラットは地表 Y=-60 なので、高さを使う実験（落下など）では、地表からの高さと Y 座標の両方を画面に出すと混乱しにくい。（根拠: [S6]）

## わかっていないこと・要確認
- Java の標準の描画で、太陽の向きに応じた影（ブロックの影）が出るかどうか。今回読んだページでは確認できなかった（Vibrant Visuals の影は統合版の記述）。T13 の撮影方法に直結する。
- Vibrant Visuals が Java Edition にあるか・いつ入るか。
- `ENABLE_FARLANDS` の目的の出典になっている gegybeans が Mojang の開発者かどうか（今回読んだページには書かれていない）。
- Java の `/time set` の値が `minecraft:` つきに変わったバージョン。（ゲームルールが `doDaylightCycle` から `advance_time` に変わったのは 1.21.11（25w44a）と 2026-11-20 に確認した【二次】[S9]。）
- 太陽の通り道に季節（日ごとの変化）がないことの直接の記述。Sun の記事は軌道が地面に垂直な円で傾き・緯度の補正がないと書く [S8] が、日によって変わらないとまでは書いていない。
- Sun の記事の『傾き・緯度の補正がない』は描画の処理（rendering logic）の話で、Java と統合版のどちらのことかは明記されていない。
- ワールドボーダーの中心が既定で Y=255 より上にある、という記述の意味（wiki 自身が情報不足の印を付けている）。
- Java Edition の距離による不具合（distance effects）・ハードリミット（hard limits）の記事は今回読んでいない。遠い場所での実験の前に読む。
- 歩く速さ 4.3 ブロック/秒は記事の概算。正確な値は泳ぎの記事では 4.317 m/秒と書かれている（[流体.md](流体.md)）。
