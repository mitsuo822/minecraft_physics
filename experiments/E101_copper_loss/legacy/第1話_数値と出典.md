# 第1話「速くするほど、銅線は近くしか届かない」数値と出典

セットは `gen_ep1.py` で生成している。数値を変えたら `python gen_ep1.py` を再実行し、ゲーム内で `/reload` → `/function photon:ep1/build`。

## 使っている数値

| 項目 | 値 | 出典 |
|---|---|---|
| 銅配線の損失 | 0.1 dB/インチ/GHz（低損失基板）。悪い基板は 0.2 | Eric Bogatin「Loss in a channel: Rule of Thumb #9」EDN, 2014 — https://www.edn.com/loss-in-a-channel-rule-of-thumb-9/ |
| 25 Gbps の受信限界 | 35 dB（12.89 GHz） | IEEE 802.3bj 100GBASE-KR4 のチャネル挿入損失上限 |
| 100 Gbps の受信限界 | 28 dB（26.56 GHz） | IEEE 802.3ck 100GBASE-KR1 のチャネル挿入損失上限 |
| 光ファイバーの損失 | 0.33 dB/km（1310 nm） | G.652.D ファイバーのメーカーデータシートの典型値（例: Prysmian G.652.D） |
| 縮尺 | 1ブロック = 1インチ（2.54 cm） | 演出上の設定 |

計算結果（60インチ = 152 cm 先）:

| レーン | 1インチあたり | 60インチで | 届く距離の目安 |
|---|---|---|---|
| 1 Gbps 銅線（ナイキスト 0.5 GHz） | 0.05 dB | 3.0 dB | 余裕あり |
| 25 Gbps 銅線（12.89 GHz） | 1.29 dB | 77 dB | 約27インチ（69 cm） |
| 100 Gbps 銅線（26.56 GHz） | 2.66 dB | 159 dB | 約10.5インチ（27 cm） |
| 100 Gbps 光ファイバー | 0.0000084 dB | 0.0005 dB | 同じ損失なら約85 km |

## 画面に出している注意書き

- 信号の進む速さは全レーン同じ（実際も、基板上の電気信号は光速の約半分、ファイバー中の光は約2/3で、桁は同じ）。
- 受信限界はコネクタやパッケージを含むチャネル全体の値。配線だけに使える距離は、実際はもっと短い。
- 「受信不能」は信号がゼロになったのではなく、小さくなりすぎて受信機が0と1を区別できないという意味。

## 単純化していること（動画で一言触れる候補）

1. **損失は周波数に正確には比例しない。** 導体損は √f、誘電損は f に比例する。経験則は 4 GHz 付近から導いた直線近似なので、高い周波数では損失をやや大きめに見積もる可能性がある（Bogatin 本人も「厳密には線形ではない」と書いている）。
2. **損失以外の劣化を入れていない。** 反射、クロストーク、モード変換。等化器（イコライザ）で取り戻せる分は、受信限界の数字に含まれている。
3. **光にも別の限界がある。** 長距離では分散（波長ごとに速さが違う）が効く。データセンター内の距離なら、1310 nm 付近では小さい。
4. **変換コストを数値で出していない。** 電気→光→電気の変換に電力がかかることだけを示した。数値（pJ/bit）は出典の質がまちまちなので、別の回で一次資料を当たってから扱う。

## 次の回へのつなぎ

「変換に電力がかかるなら、変換器をどこに置くのが一番得か？」→ 変換器をチップのすぐ横に置き、銅線を数cmにする＝光電融合（CPO）。
