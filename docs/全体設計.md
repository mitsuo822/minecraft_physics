## 2. 中心になる考え方: 実験をコードとして定義する

Minecraftは1秒20tickで決定的に動く。手順をコードにしておけば、**計測した現象と全く同じものを、何度でも、別のカメラ位置で撮れる**。
そこで `experiments/Exxx/experiment.yaml` を、台本・計測・撮影の正本にする（書式は `実験定義.md`）。

```
experiment.yaml ──┬─→ 計測の実行 → measurements.csv → 理論と比較 → results.json / グラフ
                  │                                        │
                  │                                        ▼
                  ├───────────────────────────────→ 台本（結果を見てから書く）
                  │                                        │
                  └─→ 撮影の実行（ショットごと、16:9 と 9:16）  │
                                       │                   │
                                       ▼                   ▼
                                  制作台帳 ledger.json ──→ movie（ナレーション・字幕・組立・検査・投稿）
```

## 3. 人が関わる3つの関門

全自動にはしない。理由は次の3つ。

1. YouTubeは量産型・反復的なコンテンツを収益化の対象外にしている（2025年7月に「Inauthentic content」として明文化）。人の判断が入っていることが重要。
2. APIの側では意図しない公開を止められない。YouTube Data API は、未監査のAPIプロジェクトから上げた動画を非公開に制限する方針（2020-07-28 から）を 2026-11-02 に撤回した。今は `status.privacyStatus` を指定しないと既定で公開（public）になる【一次】（[movie: knowledge/youtube/API投稿.md](https://github.com/mitsuo822/movie/blob/main/knowledge/youtube/API投稿.md) §1）。APIの制限では公開を止められないので、投稿スクリプトは `privacyStatus` を必ず `private` と明示して上げ、最後の公開は、少なくとも当面は人が行う。
   - 訂正（2026-11-20）: この項は以前「監査を受けていないAPIプロジェクトからのアップロードは非公開に固定される」と書いていた。2026-11-02 の撤回より前の方針に基づく記述だった。
3. 物理チャンネルで誤りを出すと信用を失う。

| 関門 | 人がやること | 目安の時間 |
|---|---|---|
| 1. テーマ | 採点済みの候補から選ぶ | 数分 |
| 2. 実験設計 | 仮説・理論の予測・手順が正しいかを見る | 5〜10分 |
| 3. 公開 | 完成動画とショートを見て公開（または予約） | 動画の長さ＋α |

承認の記録は `episodes/EPxxx/episode.yaml` に残す。

## 4. 2つのリポジトリの分担

| | minecraft_physics（このリポジトリ） | movie |
|---|---|---|
| 知見 | MC物理の仕様と実測、mod、MCの撮影技術、チャンネルの方針 | 編集・音声・YouTube運用の知見 |
| コード | 実験の実行・計測・理論モデル・グラフ、MC用mod・データパック | 制作台帳のスキーマ、TTS、字幕、Remotion部品、検査、アップロード |
| 出力 | 制作台帳（素材・計測データ・台本） | 完成動画（長尺・ショート） |

**境界は制作台帳 `ledger.json`。** このリポジトリは台帳を書き出すところまで、movie は台帳を受け取るところから担当する。台帳の書式は movie の `docs/制作台帳.md` が正本。

## 5. 実装の段階

| 段階 | 内容 | 完了条件 |
|---|---|---|
| **P0 環境決め** | MCのバージョンとmod構成を決める（`MC実行基盤.md` の確認事項） | `mc/mods.yaml` が確定し、サーバとクライアントが起動する |
| **P1 計測**（コード完成・模擬サーバで試験済み、実機は未実行） | RCON＋tickのコマ送りで、E001（自由落下）を自動で計測し、理論と比べたグラフを出す。撮影はしない | コマンド1つで measurements.csv とグラフが出る。手計算の理論値と一致する |
| **P2 撮影の試作** | 半自動（Flashbackで収録→カメラは手で付ける）と、全自動（自作カメラmod）を小さく試して比べる | どちらで進めるかを、所要時間と画質で決められる |
| **P3 長尺1本** | movie 側の台帳→VOICEVOX→Remotion を作り、E001 で1本完成させる | 人のコピー作業なしで、台帳からMP4が出る |
| **P4 ショート** | 9:16 の撮り直し＋ドパガキ編集のテンプレート | 長尺1本からショートが自動で出る |
| **P5 回す** | テーマ採点の自動化、投稿、視聴データの取り込み | 3つの関門以外を人が触らずに1本出せる |

最初に公開できるのは P3 の終わり。P1 の計測だけでも、知見（`knowledge/`）は貯まり始める。

## 6. このクラウド環境でできること・できないこと

- できる: 設計、知見の整理、コード（Python・mod・Remotion）を書く、台本を書く、テーマ候補を出す。
- できない: MCの実行・撮影・GPUを使う処理。これらは自宅PCで行う（自宅PCの Claude Code、または `lab/` のコマンドを手で実行）。
