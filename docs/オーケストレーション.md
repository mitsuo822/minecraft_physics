# オーケストレーション

状態: 2026-11-18。`orchestra/` に実装済み。模擬のエージェントで全工程を通す試験は済んでいる。
本物のエージェントで1本を通したことはまだない。

## 1. しくみ

```
python -m orchestra run EP002
        │
        ├─ orchestra/pipeline.yaml   工程の順番と種類（ここを書き換えれば工程が変わる）
        ├─ episodes/EP002_*/episode.yaml   その回の方針・承認の記録・各工程の状態
        │
        ├─ agent 工程   → claude -p --agent <担当> で .claude/agents/<担当>.md を呼ぶ
        ├─ command 工程 → python -m lab run …（計測）、python -m orchestra check …（数字の照合）
        ├─ gate 工程    → 人の承認まで止まる
        └─ manual 工程  → 人の作業（撮影など）が終わるまで止まる
        │
        └─ episodes/EP002_*/runlog.jsonl   実行台帳: 工程ごとの時間・終了コード・費用・結果
```

決まった処理はプログラムが、判断が要る処理はエージェントがやる。工程の順番・合否・差し戻しはプログラムが決める
（エージェント任せにすると、どこで何が起きたかを後から追えなくなるため）。

## 3. 担当とモデル

| 担当 | モデル / effort | 理由 |
|---|---|---|
| physics-reviewer | **Fable 5.2 / high** | 「数字は合っているのに誤解させる」誤りはテストで見つからず、判断でしか防げない。最も強いモデルを置く。1本につき2回しか動かないので総額は小さい。Fable は high より上で伸びがまちまちなので、high で見逃しが出たら xhigh を試す |
| physics-modeler | Opus 5.5 / high | 物理の深さが要るが、計算の誤りはテストと reviewer が捕まえる。Opus 5.5 は既定が medium なので high を明示 |
| scriptwriter | Opus 5.5 / high | 教養とエンタメを両立させる日本語の掛け合いは、チャンネルの価値そのもの。物理の正しさは reviewer と check が別に見る |
| researcher | Sonnet 5.5 / high | 読む量が多いので単価の安い Sonnet。出典の格（一次か二次か）の見分けは手を抜けないので effort は下げない |
| mc-builder | Sonnet 5.5 / medium | コード。誤りは実行とゲーム画面で見える。工程表の外で必要なときに呼ぶ |
| publisher | Haiku 5.5 / low | 既存のファイルの転記と整形だけ |
| qc | Haiku 5.5 / low | 判定はプログラム（check）がやり、結果を読むだけ |
| メイン（あなたと話すセッション） | Opus 5.5 / medium | orchestra を動かして結果を伝えるだけ |

参考価格（API、100万トークンあたり 入力/出力）: Fable 5.2 $8/$40、Opus 5.5 $4/$20、Sonnet 5.5 $2/$10、Haiku 5.5 $0.10/$0.50。
サブスクで使う場合は、この比率でおおよそ利用上限の減り方が変わる。

runlog.jsonl の cost_usd は「APIで払ったらいくらか」の換算値で、**請求額ではない**。
このPCの Claude Code は claude.ai の Max プランでログインしている（2026-11-18 に `claude auth status` で確認、APIキーは未設定）ので、
エージェントの実行は Max の利用枠を減らすだけで、別料金はかからない。ただし claude.ai の設定で「追加利用（上限を超えた分の課金）」を有効にしている場合は、枠を使い切ったあとに課金されうる。

## 4. 使い方

リポジトリのルートで、venv の Python を使って実行する。

```
python -m orchestra new EP002 --slug ice-friction --experiment experiments/E004_ice_friction --theme T04 --series A --title "氷の摩擦を測る"
python -m orchestra approve EP002 theme --by 和田
python -m orchestra run EP002          # 関門・人の作業・失敗・前提不足のどれかで止まるまで進む
python -m orchestra status EP002       # 今どこか
```

Claude Code の中からは `/ep-status EP002`、`/next EP002`、`/run-episode EP002`、`/approve EP002 design 和田` でも同じことができる。

終了コード: 0=工程完了 10=人の番 20=失敗 30=前提不足 40=差し戻し 50=全工程完了。
スケジュール実行やシェルスクリプトから使うときは、この終了コードで分岐する。

## 5. エージェントの権限

`claude -p` は次の設定で呼ぶ（`orchestra/engine.py` の ALLOWED_TOOLS）。

- ファイルの編集: 許可（`--permission-mode acceptEdits`）
- コマンド: `python -m pytest`、`python -m lab …`、`python -m orchestra check …`、`git status / diff / log` だけを許可
- それ以外のコマンドは拒否される。git の commit・push はエージェントにさせない（人が中身を見てから行う）

各担当が使える道具は `.claude/agents/<担当>.md` の tools でさらに絞っている（例: reviewer は Edit を持たない）。
