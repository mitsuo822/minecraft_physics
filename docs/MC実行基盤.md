# MC実行基盤

状態: 叩き台（2026-11-18）。下の【未確認】は P0 で確認する。

**2026-11-18 決定: 基盤は Java 26.3 ＋ Fabric。Create の回だけ 1.21.1 ＋ NeoForge の別インスタンス。** 理由と mod の一覧は `mc/mods.yaml`。

## 1. 構成

```
自宅PC（Windows, RTX 4070 Ti SUPER）
├─ MCサーバ（ローカル、Fabric 想定）  ←─ RCON ── lab/runner.py（実験の実行・計測）
│     └─ データパック / 計測用mod
└─ MCクライアント（撮影用）           ←─ 撮影の制御（段階で方式が変わる。§4）
      └─ 録画 → media/（git外）
```

## 2. バージョンとmod

方針: **計測・撮影の基盤は1つのMCバージョンに固定**し、物理を変えるmodを使う回だけ別の構成（別インスタンス）を立てる。

| 用途 | 候補 | 確認すること |
|---|---|---|
| 基盤 | Java版 + Fabric | 下の必須modがすべて揃う最新のMCバージョン【未確認】 |
| 偽プレイヤー・各種計測 | Carpet mod | `/player` で走る・投げる等の操作を再現できるか |
| 撮影（半自動） | Flashback（または Replay Mod） | 対応バージョン、カメラパスの書き出し方法【未確認】 |
| 画質 | Iris（シェーダー）、Distant Horizons（遠景） | 録画の負荷。実験の見やすさを損なわないか |
| 構造物の配置 | 構造ブロック / WorldEdit | Pythonで生成した .nbt を配置できるか |
| 物理系の題材 | Create、Valkyrien Skies 2 など | Create の本流は Fabric 以外のローダーの可能性あり【未確認】。その回だけ別インスタンスにする |

決まったら `mc/mods.yaml` に、modの名前・バージョン・入手元・ライセンスを書く。

## 3. 計測: tickのコマ送りでログを取る

まずは**mod開発なし**の方式で始める。

1. `/tick freeze` で世界を止める（1.20.3以降のバニラのコマンド）。
2. 実験の手順を `experiment.yaml` に書いたtickで実行する。
3. `/tick step 1` で1tick進め、RCONで `data get entity <対象> Pos` と `Motion` を読み、CSVに追記する。
4. 終了条件まで繰り返す。

- 長所: 1tickごとの値が漏れなく正確に取れる。バニラのコマンドだけでできる。
- 短所: RCONの往復が1tickごとに入るので、実時間よりずっと遅い。長い実験では遅すぎるかもしれない。
- 遅すぎる場合: サーバ側modで毎tickの値をファイルに書き出す方式に移る（P1で実測して判断する）。
- 確認すること: `/tick step` 中もエンティティの物理が通常のtickと同じに進むか【未確認】。E001 で、普通に動かしたときの着地tickと一致するかを見る。
- 実装済み（2026-11-18）: `lab/runner.py`。`tick step 1` は非同期に進むので、`time query gametime` が1増えるまで待ってから読む。
  プレイヤーがいないとサーバが一時停止する設定（`pause-when-empty-seconds`）は0にする（`mc/server/`）。

CSVの列（案）: `tick, target, x, y, z, vx, vy, vz, on_ground`

## 4. 撮影: 段階を踏む

サーバからのテレポートでカメラを動かすと、20tick/秒の刻みでカクつく。滑らかにするにはクライアント側の制御が要る。

| 段階 | 方式 | 自動化 | 開発量 |
|---|---|---|---|
| 半自動 | 実験をサーバで再実行 → Flashback で収録 → カメラパスは人がGUIで付けて書き出す | 収録は自動、カメラは手作業 | ほぼなし |
| 全自動（試作） | 自作Fabricクライアントmod: `experiment.yaml` の `shots` を読み、カメラを補間して動かしながら録画する | 全部自動 | 中〜大 |
| 全自動（発展） | tickを止めたまま、カメラを動かして1コマずつ画面を書き出す（コマ撮り）。任意のスロー・任意のfpsで撮れる | 全部自動 | 大。`/tick freeze` 中のクライアント側の描画の動きを要確認【未確認】 |

P2 では、半自動と全自動（試作）を同じショットで比べて、どちらで進めるかを決める。

## 5. 決定的に再実行できる条件

撮影と計測の結果を一致させるために、次を固定する。

- ワールド: 実験用のフラットワールドを毎回作り直す（シード固定）。
- `doDaylightCycle false`、`doWeatherCycle false`、`randomTickSpeed 0`、`doMobSpawning false` など、乱れの元を止める。
- 乱数を使う現象（TNTの爆発の向きなど）は「完全には一致しない」ものとして扱う。計測はN回繰り返して分布で示し、撮影は見栄えのよい回を選ぶ。
