# 実験定義の書式（experiment.yaml）

状態: 叩き台（2026-11-18）。P1 の実装に合わせて変える。

1つの実験 = 1ディレクトリ。

```
experiments/E001_free_fall/
  experiment.yaml     # 正本（この文書の書式）
  notes.md            # 設計の意図、試した結果のメモ
  results/            # 計測結果（小さいCSV・JSON・グラフはgitに入れてよい）
    run_YYYYMMDD_HHMM/
      measurements.csv
      results.json      # 理論との比較、結論
      plot_*.png
```

## 項目

| キー | 必須 | 中身 |
|---|---|---|
| `id`, `title` | ○ | 実験のIDと名前 |
| `mc_version`, `profile` | ○ | MCのバージョンと、mod構成の名前（`mc/mods.yaml` の構成名） |
| `question` | ○ | 視聴者への問い（フックになる） |
| `hypotheses` | ○ | 予想。現実の物理による予想と、よくある誤解を両方書く |
| `theory` | ○ | 理論モデル（`lab/models/` のPython）と、その確度 |
| `world` | ○ | ワールドの作り方、ゲームルール |
| `setup` | ○ | 装置（構造物）、追跡するエンティティ（`id` を付ける） |
| `procedure` | ○ | tickごとのコマンド |
| `measure` | ○ | 追跡対象、記録する値、終了条件、繰り返し回数 |
| `analysis` | ○ | 何と何を比べて、何を結論にするか |
| `shots` | | 撮影するショット。`aspect` で 16:9 / 9:16 を指定 |
| `approval` | | 関門2の承認記録（誰が・いつ） |

## 決まり

- `procedure` のコマンドはバニラの書式で書き、tickは実験開始（`tick unfreeze` の時点）からの相対値にする。
- 追跡するエンティティには `Tags` で `track_<id>` を付ける。計測はタグで探す。
- 理論値は必ずコード（`lab/models/`）で出す。yaml に手計算の数字を書かない。
- `shots` のカメラ位置は装置の座標系で書く（装置を置く場所が変わっても使えるように）。
